## 一、对高位接力（地基均线反包明细.csv）

- 交集 = 该库断 1~3 天 × 前波高 2~5 板的行，共 181 行；
- 三要素（代码 / 末板日=前板日 / 断板天数 / 高度=N）配上 **174**，且 **174/174 反包日 ==
  该票高位接力首板日**——同一事件的两种视角（反包研究买反包板、高位接力买其后的接力板）完全对齐；
- 漏 7 行（去重 5 事件）已逐笔查日线核实：**反包日全部一字板**（open=high=low=涨停价），
  按「一字买不进剔除」口径排除，非 bug。

## 二、对 N 型补涨打板（V4四组全量.csv）

- 口径换算：N 型「坑宽」= 末板日→D0 的交易日距离 = **断板天数 + 1**（含首日），对账前已换算；
- 交集 = 坑宽 2~4（断 1~3 天）× 上波高 2~5 × 昨非涨停 × 2023 年起，共 784 行，配上 **759（96.8%）**；
- 漏 25 行全部核实为**口径定义差异**，非数据错误：
  - N 型「上波高」= 20 日窗口内最大连板；反包库要求**紧邻前波**高度。
    典型形态「2 板 → 断 1 天 → 反包封住（成 1 板）→ 断 1 天 → 再触板」：N 型记 2 板系信号，
    反包库按紧邻段判 N=1 排除；
  - 其余为 2023 年前老样本（反包库起点 2023-01）。
- 该差异留档：Phase 1 可把「窗口内有更高前波」单独切分验证是否毒点（对应需求文档待拍板点 5）。

## 三、案例门禁（独立代码路径重算）

- 抽样 = 主 12 格每格 2 笔 + **5板×断1天格全量 46 笔**（Phase 0 最亮格重点验），共 68 笔；
- 独立实现：纯 SQL 逐票拉原始日线 + Python 逐日循环判连板/断板/触板/一字/买价/收益，
  与主脚本的向量化路径零共享代码；
- 结果：**68/68 全部一致**（末板日 / N / 断板天数 / 断板期每日不涨停 / 触板 / 非一字 /
  买价 / 封住 / 次日收% / 持有到断板%）。

## 四、过程中发现并修正的问题（备忘）

1. 涨停价舍入边界：`昨收×1.1` 落在 x.xx5 时，浮点表示略小于真值，不加 `1e-9` 会舍反方向
   （例：21.95×1.1=24.145 → 应为 24.15，纯 round 得 24.14）。主脚本 `+1e-9` 与交易所四舍五入
   一致（高位接力 relay 系列已与数据库买价逐笔对过账）；门禁脚本初版漏加，首轮 36 笔不一致
   全部由此产生，修正后归零。
2. 容器 pandas 旧版 `groupby.apply` 与宿主机新版行为不同（组键列会产生 NaN 行），抽样改用
   逐组收集索引再 loc 的写法，两版本一致。

Phase 0 数据通过三道验证（两库交叉对账 + 独立重算门禁），口径与高位接力、N 型补涨打板
互洽自洽，可进入 Phase 1 好差票对比。
