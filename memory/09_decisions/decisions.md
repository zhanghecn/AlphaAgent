# Decisions

这个文件记录仍然有效的长期决策。按日期产生的验证过程、接口输出和截图不放在这里；需要证据时链接到 `memory/06_backtests/`、`docs/plans/` 或具体源码。

## Project Boundary

- 项目外显名称是 AlphaAgent，目标是基于 vn.py 做服务端化 A 股量化研究、智能选股、策略回测、模拟持仓和后续交易工作流。
- 保留 Python 包名和源码目录 `vnpy`，不重命名为 AlphaAgent，避免破坏 vn.py 插件依赖和已有导入。
- 不修改继承的 `vnpy/` 核心包和官方 examples，除非用户明确要求或项目兼容性必须修改。
- AlphaAgent 自研业务层放在 `alphaagent/`、`frontend/`、`docs/`、`requirements/` 和 `memory/`。
- 需求分析和产品设计放在 `requirements/`，长期项目事实放在 `memory/`。

## Collaboration And Git

- 不主动 `git commit` 或 `git push`。只有用户明确要求“提交”或“push”时才执行。
- 工作区可能包含用户或前序模型改动，不能随意 revert、reset 或 checkout。
- 提交前优先做可验证的小步整理：编译、定向测试、前端 build、`git diff --check`。
- `memory/` 是项目地图，不是日记。新增事实时优先改写现有 overview，长报告放到 typed artifact。

## A-share Capability

- 当前 vn.py GUI 只注册 CTP，不能声称已经接入 A 股实盘或全 A 实时行情。
- A 股实盘交易应通过官方或兼容 Gateway，例如 XTP、TORA、OST、EMT。
- 历史数据应优先通过可验证的数据源或插件，例如 XT、RQData、Tushare、券商/QMT/TDX/vn.py 本地库。
- 免费公共分钟源只能作为近端补充，不能直接当作长区间严格回测依据。

## Quant Product Shape

- `/quant` 是量化研究工作台，主路径为一键策略研究、候选查看和组合回测归因。普通用户视图只保留“候选/回测”两个入口；数据质量、日志、分钟模型等只作为高级/内部复核能力，不放在普通主流程。
- `/portfolio` 是独立持仓模块，负责自选分组、量化候选分组、模拟持仓、成本价、买卖依据。
- 股票详情页 `/stocks/:vtSymbol` 承接单股回测、K 线买卖点、财报口径和组合回测复核。
- 量化页默认只展示组合回测；股票详情页生成的单股回测不混入量化页主列表。
- 股票展示尽量使用“名称 + vt_symbol + 板块标签”，并复用可点击的股票身份组件。
- 用户界面和 API message 不暴露 `replay` 这类内部工程词；统一称为“买卖记录”或“买卖执行记录”。接口路径、字段名和表名可先保持 `replay` 以避免兼容性迁移。

## Candidate And Strategy Rules

- 组合回测必须使用历史逐日动态候选：每个信号日只使用当日及以前可见数据生成候选，再在下一交易日执行。
- 前端只暴露“刷新候选并回测”主操作：页面调用 `POST /api/quant/research-runs` 创建后台研究任务并轮询状态；任务内部从用户选定交易日跑到本地最新交易日，自动补候选、生成买卖记录并运行组合回测。
- 候选区间生成是内部主量化过程；`persist=true` 时会跳过已存在成功交易日，只补缺失日期，并基于已落库 `quant_stock_signals` 生成统一 `strategy_replay_runs` / `strategy_replay_attempts`，不再让股票详情默认单独重算一套单股缓存。
- 量化页候选 tab 展示候选和自动回测状态，不再要求用户单独理解或手动触发“生成区间候选/生成执行复盘”。“产品口径”指展示、命名和业务解释口径收敛，不代表拆页面或新增复杂入口。
- 候选页不拆复杂多入口；低吸洗盘、龙回头、风险拒绝等都作为同一候选评分和解释字段展示。默认观察评分前 `100` 个候选并分页显示，每页 `20`；组合模拟默认最大持仓 `10`、执行 BUY 候选前 `20`。观察前 `100` 只方便用户审查评分排序，不会强行保留低吸名额，也不会扩大真实执行池。
- 候选评分必须可解释：候选行或股票复核中应能看到“为什么这个分数”，包括状态、低吸蓄势天数、均线收敛、低吸蓄势分、失败规则和评分拆解，避免用户只看到黑盒总分。
- 候选、股票详情、量化候选分组和组合执行 action 必须一致：`entry_signal` 是原始诊断字段，只有 `executable_entry_signal=true` / `action=BUY` 才显示为可买入、计入 BUY 次数并进入买入计划；硬信号低于 `min_entry_score` 或存在失败规则时展示 `WATCH`，不能显示为可买入的 `BUY`。
- 量化页候选默认日期优先选择当前公开策略最新已生成候选日；如果最新交易日尚未运行，不应默认展示空候选误导用户。工作流卡片必须同时显示本地日线最新交易日和候选最新日期，明确暴露候选滞后。
- 量化页候选 KPI 使用当前选中交易日实际推荐数；分组同步数只作为同步状态，不作为“候选数量”主指标。
- 量化页组合回测列表按当前公开策略和当前注册版本过滤；旧策略或旧版本回测不能挤掉当前策略回测。
- 普通用户入口只公开 `mainline_dragon_pullback` 一个策略；策略仍通过注册表管理，避免在 API/UI 里硬编码散落。
- 旧 `mainline_leader_pullback`、`breakout_confirmation`、`limit_up_after_pullback`、`trend_acceleration` 只保留为内部兼容和旧报告/对比工具能力，不再出现在普通策略列表和主流程下拉中。
- `WATCH` 只表示观察，不应作为自动组合买入信号；买入计划只应来自 `action=BUY` 并通过组合约束的候选。
- 量化候选分组的 reason JSON 也必须同步 `action`、`raw_entry_signal`、`executable_entry_signal` 和 `failed_rules`，前端展示优先读 `action`，不能只看原始 `entry_signal`。
- 下一阶段回撤/排序优化计划见 `requirements/alphaagent_strategy_drawdown_optimization_plan.md`，当前只是执行计划而非已上线策略：信号只作为买点/拒买证据，卖点应以买点成本/支撑为锚，结合持仓最高浮盈回撤、当前支撑结构和当前日买入/持有状态动态计算；高位已有浮盈后从最高价突然回撤约 `7%` 应作为疑似出货的回撤止盈实验条件。高位横盘出货风险以 `603226.SSE` 为重点样本，初始按至少约 `15` 到 `20` 个交易日的高位窄幅横盘定义“横久”，但必须验证不误伤短期正常龙回头回踩。低吸涨停启动四因子作为待验证的低吸质量增强证据：近 `20` 日涨停/近涨停、`4`/`5` 连阳、上涨段向上跳空缺口、持续倍量/放量；只有证明能提高弱市/震荡市低吸胜率后才可加小额排序分。候选展示只显示选中的买点、拒买和卖出，不展示密集观察日流。

## Backtest Execution

- 普通新建组合回测默认执行模型是 `legacy_next_open / strict_entry=true`：D 日收盘产生信号，D+1 按日线开盘价执行买入和卖出。
- 历史主流程不再依赖 `14:30` 分钟线。14:30/分钟快照只保留为未来实时数据、盘中确认、分钟数据同步和旧报告兼容能力。
- BUY 信号不等于实际购买。BUY 信号表示 T 日收盘后策略生成买入计划；实际购买必须经过 T+1 执行价、涨停/跌停、现金和仓位等约束。
- `mainline_dragon_pullback` 组合满仓时允许有限换仓：只有 `total_score >= 98` 的新鲜 `TAIL_BUY_READY` BUY，才可替换浮盈不超过 `+3%`、持有不少于 `3` 天且入场分不高于新信号的持仓；默认最大持仓仍是 `10`。
- 执行拒绝原因必须精确区分：`limit_up_open_blocked` 是开盘涨停买不到，`limit_down_open_blocked` 是开盘跌停卖不出，`no_execute_bar` 是缺执行日 K 线，不能再合并成“涨停或缺数据”。
- `tail_close_hybrid` 和 `strict_1430` 保留为研究对比/旧报告兼容模型，不能当作当前历史主流程。
- `strategy_version < 0.1.1` 只作为旧报告兼容，旧绩效不作为当前策略结论。

## Single-stock Review

- 股票详情页默认优先读取最新组合回测的该股详情，并提供 `交易复盘 / 候选信号` 切换。`交易复盘` 只看真实组合订单、成交、拒绝执行和闭合收益配对；`候选信号` 只看理论候选/信号标记。再读取 `/api/quant/symbols/{vt_symbol}/latest-state` 的最近全局量化过程状态补充评分、BUY 信号、候选计划、买卖记录和拒绝原因。个股页不暴露日期选择和手动单股回测入口，避免用户看到与全局量化过程不一致的第二套口径。
- 股票详情页不能用早于最新候选日期的旧买卖记录覆盖新候选状态；如果最新 `strategy_replay_runs.end_date` 早于最新 `quant_signal_runs.trade_date`，详情页状态应回退到最新候选筛选，并标记过程滞后，直到新的全局买卖记录生成。
- 股票详情页固定使用公开策略 `mainline_dragon_pullback`，先读取最新组合回测下该股的真实执行标记；若组合回测里没有该股执行记录，再使用最近全局买卖记录/信号；仍没有执行标记时才后台准备同策略单股买卖点缓存。不要恢复“运行手动研究回测”按钮或多策略下拉。
- 股票详情页如果最新组合回测已经有该股订单/成交，则 K 线展示同一组合回测口径的实际订单/成交标记，并叠加同一回测的理论信号计划；不再叠加独立全局买卖记录的 `already_holding` 信号噪音。全局买卖记录只作为无组合执行记录时的兜底。
- 股票详情页会抑制已关联真实成交订单的同回测理论 BUY 标记，避免同一信号同时显示“信号”和“买”两条重复标记；仍保留没有真实成交的理论信号用于解释历史机会。
- 股票详情页候选信号视图只显示聚合后的关键候选买点和买拒：连续 `3` 个自然日内多个可执行 BUY 只保留最高分点，纯观察类低吸蓄势 WATCH 不画 K 线标记，原始买点但失败规则未通过的 WATCH 显示为买拒。真实买入、卖出和拒单不参与该候选聚合过滤。
- 持仓中心的持仓卡读取 `/api/quant/symbols/{vt_symbol}/replay/latest` 派生策略建议，显示“策略持有 / 策略已卖出 / 卖出待确认 / 买入未成交 / 无买卖记录”等状态；后续如持仓数量变大再加批量买卖记录 API。
- 持仓中心不再把模拟账户金额作为用户主功能暴露；批量建仓、手动加入和加仓按股数/最小整手操作，KPI 和卡片以收益率、价格、股数和策略建议为主，持仓收益率按持仓股票收益率做算术平均，不再用市值金额加权展示。
- 股票详情页单股复盘不展示模拟账户金额，不以 `initial_cash/final_equity/cash/equity/amount/fee/pnl amount/volume` 解释单股收益。
- 单股收益率按闭合成交价格直接计算：单笔收益率为 `sell_price / buy_price - 1`，累计收益率为各闭合单笔收益率连乘。
- K 线图必须同时显示可执行 BUY 信号、买入拒绝、买入成交和卖出成交；即使本轮买卖记录没有 execution attempt，只要 `quant_stock_signals` 存在 `action=BUY` / `executable_entry_signal=true` 也要显示信号标记。原始 `entry_signal=true` 但 failed_rules 未通过时只作为 WATCH/买拒解释，不画 BUY 信号。点击 K 线或指标柱显示当日涨跌、跳空、振幅、均线距离、量比和相关信号/执行标记。

## Data Rules

- 回测评分只使用 `publish_date <= trade_date` 的财报，股票详情看到的当前财报不等于历史回测当天可用。
- 股票日线成交额入库单位必须统一为元；旧数据缺成交额时可用 `close * volume * 100` 估算流动性。
- 分钟数据补数属于实时/分钟数据层，不是历史策略研究主流程；如需旧严格分钟报告或未来盘中确认，应优先走同步/导入服务：`sync_stock_minute_bars mode=backtest_gaps`、TDX、Tushare、vn.py 本地库或供应商数据。
- CSV/file_path 是外部供应商回填和高级兜底，不是首选日常补数方式。
- API 必须区分日线开盘执行、实时分钟执行、收盘代理、缺快照、入场未触发和涨跌停/现金/仓位拒单。

## Current Strategy Evidence

- `requirements/alphaagent_pullback_low_suction_strategy_research.md` 已更新为当前回踩低吸优化研究结论：普通产品入口只公开 `mainline_dragon_pullback / 0.1.21`，低吸洗盘和龙回头在同一公开策略内作为内部 setup，不拆 UI，也不把低吸洗盘简单作为龙回头原始信号加分项。
- `mainline_dragon_pullback / 0.1.21` 是当前普通历史研究唯一公开策略代码；旧 `mainline_leader_pullback / 0.1.1` 和 `mainline_dragon_pullback / 0.1.0/0.1.1/0.1.3/0.1.6/0.1.8/0.1.9/0.1.11/0.1.14/0.1.15/0.1.16/0.1.17/0.1.18` 保留为内部备份/历史对照。
- `0.1.21` 保留低吸洗盘识别和严格执行线，但取消低吸固定保留名额。低吸天数可在 MA5/MA10/MA20 承接、缩量、MA20 未破、回撤受控和 MA 收敛改善时累计；至少 3 天吸筹后的首个温和拉升可确认 `stealth_low_suction`。低吸不再被经典龙回头的 `pullback_too_late` 硬压制，但派发、MA20 破位、回撤过深、过热、流动性和风险分仍是硬风险。
- 低吸涨停启动四因子已实现为诊断和审计字段，不能直接作为默认买入加分。`#190/#175` 审计显示 `stealth_low_suction` 闭合交易 `83` 笔中，`3-4` 因子桶胜率约 `28.57%`，未优于 `0-1` 因子桶约 `30.77%`；赢家平均因子数 `1.92`，输家 `2.02`。连续上涨标签上有弱正相关，`3-4` 因子桶 MFE>=8% 约 `42.86%`，高于 `0-1` 的 `30.77%`，但弱/震荡市场里 `3-4` 因子桶胜率仅约 `13.33%`。结论见 `memory/06_backtests/2026-06-18_low_suction_start_factor_audit.md`。
- 顶分型、毛刺剧烈震荡、高位放量滞涨、关键支撑破位、成交极度萎靡和高位久横派发已先实现为 `mainline_dragon_pullback` 的风险证据字段。当前默认只把关键支撑破位和明确高位放量滞涨纳入失败规则；周线顶分型、毛刺自玩、低流动性遗忘、高位久横等先作为诊断/扣分，不得在未跑全局回测前宣称能提升收益或胜率。
- 低吸执行/换仓实验边界：`0.1.12/#162` 的 top20 外低吸补充执行池收益仅约 `+30.19%`，拒绝；`0.1.13/#163` 执行前 20 内低吸替换低效持仓可把回撤降到约 `-16.71%`，但收益降到约 `+46.88%`，拒绝作为当前基线；`0.1.15/#165` 收益约 `+55.41%`、最大回撤约 `-21.17%`，低吸覆盖改善但收益下降；`0.1.16/#167` 收益约 `+28.80%`，过度保守；`0.1.17/#168` 收益约 `+39.16%`、最大回撤约 `-27.63%`，低吸机会加分过宽；`0.1.18/#169/#172` 是上一版稳健基线。当前 `0.1.21/#190` 收益约 `+81.32%`、最大回撤约 `-15.59%`，作为当前代码证据。
- 卖出侧买入当天硬破位次日撤退实验 `0.1.20/#174` 已拒绝并撤回：同区间收益约 `+51.51%`、最大回撤约 `-19.00%`，最大回撤只微幅改善但收益、profit factor 和 Sharpe 明显弱于 `0.1.18/#169`。它释放仓位后引入更多低质量交易，并错过部分趋势大肉票；不应继续用“日线买后立即失败就统一早卖”作为默认规则。
- 卖出侧早期连续破位止损实验 `0.1.19/#173` 已拒绝并撤回：同区间收益约 `+54.40%`、最大回撤约 `-19.79%`，弱于 `0.1.18/#169`。它把 `support_stop` 亏损拆成更早的 `early_breakdown_stop`，但同时减少趋势大肉票收益；日线 D+1 下许多大亏来自隔夜跳空，不应重复用宽泛早期破位止损作为默认规则。
- 用户展示口径：量化页不拆成多个主流程，用户主操作仍是“刷新候选并回测”；候选页按评分展示观察前 `100` 并分页，组合执行 BUY 前 `20`，最大持仓 `10`。低吸洗盘、龙回头、均线承接、资金热度和风险破位都是同一候选评分的分数来源、扣分项和拒买原因，“为什么这个分数”直接显示在候选表和股票详情复核里。
- 单股低吸排查必须分清三层：`raw_entry_signal` 是策略形态成立，`executable_entry_signal/action=BUY` 是通过当前产品执行线，组合订单/成交还要通过排名、最大持仓和换仓规则。单股逐日看 `GET /api/quant/symbols/{vt_symbol}/signal-history`，组合没买原因看 `GET /api/backtests/{id}/candidate-trace?vt_symbol=&signal_date=`。
- 回测里的“信号计划”只作为买卖计划复核表展示日期、股票、方向、价格、评分、订单状态和原因；不再让用户输入或查看总资金、每笔预算、预览金额和预览盈亏。
- 普通 `/quant` 回测页不再把“信号计划”作为独立 tab 暴露；买卖信号到订单链路通过候选行“回测成交”和股票详情 K 线解释，避免普通用户理解一套额外流程。
