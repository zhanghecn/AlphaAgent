# Decisions

这个文件只记录仍然有效的长期决策。量化实验结果、回测编号、接口输出和单次验证记录统一放在 `memory/06_backtests/` 或对应 typed memory 文件里。

## Project Boundary

- 项目外显名称是 AlphaAgent，目标是在 vn.py 基础上建设 A 股量化研究、智能选股、组合回测、模拟持仓和后续交易工作流。
- 保留 Python 包名和源码目录 `vnpy`，避免破坏 vn.py 插件依赖和已有导入。
- 不修改继承的 `vnpy/` 核心包和官方 examples，除非用户明确要求或兼容性必须修改。
- AlphaAgent 自研业务层放在 `alphaagent/`、`frontend/`、`gateway/`、`deploy/`、`requirements/` 和 `memory/`。
- 需求分析和产品设计放在 `requirements/`；长期项目事实和决策放在 `memory/`。

## Collaboration And Git

- 不主动 `git commit` 或 `git push`；只有用户明确要求提交或推送时才执行。
- 工作区可能包含用户或前序改动，不能随意 revert、reset 或 checkout。
- 提交前优先做可验证的小步整理：定向测试、编译、前端 build（`pnpm -C frontend build` / `pnpm -C frontend test`）、`git diff --check`。前端单测用 vitest（配置在 `frontend/vitest.config.ts`），纯逻辑抽到 `src/features/**/*.ts` 配 `*.spec.ts`，UI 组件靠 tsc + vite build + 浏览器实测。
- `memory/` 是项目地图，不是日记。新增事实时优先改写 overview，长报告放到 typed artifact。

## A-share Capability

- 当前 vn.py GUI 不能被描述为已经接入 A 股实盘或全 A 实时行情；A 股能力主要来自 AlphaAgent 自研业务层和后续官方/兼容插件接入。
- A 股实盘交易应通过官方或兼容 Gateway，例如 XTP、TORA、OST、EMT。
- 历史数据应优先通过可验证数据源或插件，例如 XT、RQData、Tushare、券商/QMT/TDX/vn.py 本地库；免费公共分钟源只能作近端补充，不能直接当作长区间严格回测依据。

## Deployment

- 部署统一入口是 Go 网关 `alphaagent-gateway`，对外唯一端口；`alphaagent-api` 和 `alphaagent-web` 只暴露内部端口，避免绕过登录直连。
- 管理员登录使用环境变量 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD`；登录态用 JWT HS256，前端存 `localStorage` key `alphaagent_token`。
- 发版走 `.github/workflows/docker-release.yml`，推 `v*` tag 发布 `alphaagent-api/web/gateway` 镜像到 GHCR。
- 本地开发和生产结构保持一致：网关入口、runtime web、compose 管理。旧 5173 dev server 和 api/web 直连模式不作为默认口径。

## Quant Product Shape

- `/quant` 是量化研究工作台，普通用户主路径是候选 Top5/Top10/Top20 的 D 收盘买入、D+1 收盘验证质量。组合回测/组合诊断只能作为执行层诊断，不能替代 `/quant` 主结果。
- `/portfolio` 是独立持仓模块，负责自选分组、量化候选分组、模拟持仓、成本价和买卖依据。
- `/stocks/:vtSymbol` 是股票详情页，承接单股复盘、K 线买卖点、财报口径和组合回测复核。
- `/mainline` 是概念指数页（板块排名 + 成分股），统一时间轴：合并 live 最新资金流日 + history 评分日，默认选中最新；选中 == liveDate 走实时数据（盘中刷新），其余走历史 snapshot，不再分"今日实时 / 历史回放"两个 tab。顶部"概念资金流"条带读 live/snapshot 的 `flow_top` 字段（后端 `_compute_flow_top` 从**全部概念**按主力净流入算 top10 流入/流出，独立于 `_sort_live_concept_ranking` 截断——避免 broken 概念如 CPO/光通信被 _sort 后 limit 截断挤出），双列紧凑展示，每行可点击 → 选中该概念并滚动到三栏看成分股（复用 SectorStocksTable），不归主题——游资看的是具体概念（半导体/AI/白酒/猪肉）而非抽象主题。条带顶部支持周期切换（今日/3日/5日/10日/20日；3日/20日=SUM(即时) 最近N交易日，`actual_days` 反映数据保留约11天）+ 搜索框（`/concept-search` 按 name 模糊搜全部概念，定位 CPO/PCB 等不在 top10 的概念）。即时资金流（sector_fund_flows）只保留约 11 天，更早历史日资金流字段为空属正常（数据保留策略，非 bug）。定时同步保留 14:30 实时尾盘量化、18:00 盘后同步和 21:30 晚间日线补全；旧 11:30、14:00、15:00 盘中缓存档由启动种子逻辑禁用。成分股按核心行业过滤：`/sector-stocks?industry_filter=true` 取概念成分股与申万行业重叠 top2 的交集，过滤东财概念宽泛杂股（半导体概念去掉家电/教育/机械设备股，保留真半导体）；`_STYLE_STATUS_KEYWORDS` 过滤指数篮子/风格标签（HS300_/专精特新/创业板综/标准普尔 等）让真题材进 top10。
- `/limit-up` 是独立的主板打板研究工作台：普通候选只允许热门板块龙一/龙二进入市场龙 Top5；妖股没有额外名额，仍需凭身位、资金和封板强度进入 Top5。创业板、科创板、北交所、ST/退市/特殊股不进入。
- Top5 排名不等于可成交。09:31 前封死且没有开板的秒板/一字板必须判为不可成交；保守回测只把开板回封作为成交代理，乐观成交只作敏感性分析。Tick/L2 补齐前不接自动或实盘交易。
- `/limit-up` 支持按有效交易日切换历史 Top5。历史排序不得使用当日最终封单、最终开板次数或最终是否封住；这些字段只用于盘后结果、代理成交和 D+1 收益。历史事件日期必须与 `stock_daily_bars` 交易日历相交；唯一例外是尚未生成收盘日线但已由今天 live、非 stale 快照证明的当前交易日。周末或异常快照不能进入日期列表，非交易时段的当前动作必须降为 `pass`。
- `/limit-up` 研究 Top5 不等于买入动作。后端先用 D-1 情绪、金银手指时效、分板位成功率、板块热度/资金/扩散、个股资金和量能压缩研究计划，再输出 `现在打 / 尾盘打 / 明早竞价` 三通道和确定动作；历史验证另分为当日竞价首板、盘中扫/回封、尾盘确认、明早竞价二三板四路径。
- `/limit-up` 盘后持续展示下一交易时段观察：15:05 初步计划、19:00 正式计划、21:30 和 API 启动补偿。15:05 必须由供应商涨停池日期确认当天，不能拿上一交易日计划冒充；正式计划优先且周末保持可读。盘后观察与次日竞价买点确认是两层状态：观察池只容许明确白名单中的未决/风险项，未知阻断项和涨停基因、基本面、板块地位、前板路径等硬伤继续淘汰；已有空计划自动重建，每板位最多 4 只。09:15-09:19 只能观察，09:20 后硬门全通过才显示“买点触发（人工确认）”。计划状态和执行许可必须分离，当前执行许可始终是 `research_only`；GET 只读、不得补建或写快照。
- 当前分战法基线固定为 `limit-up-history-v11` 的 600 个交易日：前 120 日预热、随后 360 日滚动样本外、最后 120 日锁定留出，并单独要求 `2026-07-12` 规则冻结后的新前向样本。首板必须同时满足半年触板至少 6 次、点时已披露净利润同比至少 10%、D-1 炸板率至少 35%、低位/冷却回调、10:00 后首次触板和盘中承接门；不再使用固定 4%-6% 局部涨幅区间。实时 D-1 弱情绪只有在封板增加、炸板减少且炸板率不高于 35% 时确认修复；仍只展示板块前二和市场 Top5，接力缺前板路径或不是行业龙一/龙二仍淘汰。
- `/limit-up` 产品层只展示一个“综合首板”，复用正式 `first_board` 排名、动作、10 万元四仓共享现金回测和交割单；不提供预热、质量门、延续或轮动的独立策略、面板和开关。板块预热仅允许作为低位首板的 `research_only` 后端证据，不得影响一进二、二进三或高板。后端研究仍拆成延续质量门和日内轮动两个通道；轮动只接受 2026-07-13 后真实非陈旧盘中快照上的同日正概念资金、动态龙一/龙二、概念内至少两只触板及封板前观察证据，禁止用历史日线或收盘结果回填。两通道统一用 10 万元、四仓共享现金账户比较；轮动没有 D+1 闭合时双通道必须与延续账户完全相同。所有影子字段不得改变 `action`、战法排名或组合选择；正式升级仍要求不少于 500 日点时概念数据、至少 100 笔正式样本和冻结后 30 笔前向闭合交易。
- v11 账本由 `eod_finalize_2130` 自动续建；无新完整日线直接跳过，有新日才重建。每个交易日必须同时保存完整板位候选池、最终 0-4 只组合选择、六类形态标签和逐笔退出决定；交割单只读组合最终选择。v10 固定退出结果保留为基准对照。
- `/limit-up` 实时默认“组合”必须复用历史回测的 `select_daily_lane_portfolio`，保持最多 4 只、同板块最多 2 只、首板/二进三/高板的相同边界；不能在前端重新发明一套选股。7% 雷达只扩大提前发现池，不扩大可买组合；Top5 先按尚可参与状态和板位硬门排序，雷达列表再按距板距离、TBOX、历史平滑胜率和战法复利排序。硬门通过且 `research_action=buy_now` 时显示“买点触发（人工确认）”，自动 `action` 仍受验证门控制；硬门失败、首次发现已封死分别显示“今日不买”和“错过不追”，不得继续统称观察。
- `/limit-up` 产品主回测固定为 10 万元、4 仓共享现金账户，默认使用系统逐笔动态退出，只执行首板、二进三和高板；一进二因滚动样本外持续负贡献仅保留独立研究。600 日全历史为 244 笔闭合交易、`62.2951% / +217.9010% / -10.3577%`，滚动样本外为 128 笔、`57.8125% / +103.0201% / -10.3577%`，锁定留出仅作验证且为 115 笔、`66.9565% / +51.9221% / -6.6170%`。固定 D+1 尾盘基准仍是 `61.7284% / +203.7969% / -10.3577%`；旧日等权结果只显示为信号研究上界。冻结后前向仍为 0，因此继续 `research_only / simulation_eligible=false`。
- 动态退出只能使用 D+1 决策日前已成熟样本，锁定留出使用开发期冻结策略。样本不足默认尾盘；当前只允许高板竞价收益达到冻结阈值约 `2.1996%` 时竞价兑现，其他信号 D+1 尾盘退出。全历史竞价价格仍是日线开盘代理，不能称为真实 09:25 撮合。
- 夹板、回马板、弱转强突破、龙首阴接力、龙头弱转强和反核板是信号时点解释标签，不直接加分、不绕过硬门，也不能因历史标签收益较好推断因果。
- `/limit-up` 的成功板/砸盘因子审计固定为 Top5 候选结果，不是成交回测。因子只能按滚动样本外区间排序，最后 120 日锁定留出只验证方向，不能反向改排名或阈值；D 日最终封住等盘后字段只能解释结果，不能用作买前特征。
- `limit-up-walk-forward-v5` 按完整交易日历使用 252 日窗口、末 63 日校准、后 63 日测试和最后 120 日旧留出，并加入当前首板选择门对照。首板事件池已经以触板为条件，成交概率不再用全真标签拟合；封板、盈利和净收益模型仍每日最多 1 只，最低训练样本 300 不为产生交易而降低。
- 模型升级必须同时通过样本数、留出正收益、利润因子、回撤、双倍成本、正收益季度、集中度、冻结概率校准、逐日历史成员和非代理成交证据。零笔策略的 0%收益/回撤不得判通过。当前四个板位模型最大单窗训练样本分别为 `314 / 198 / 43 / 17`；首板拟合 1 窗但盈利 AUC 仅 0.5221、严格选择 0 笔，其余三板位仍 `insufficient_training`。
- 只要行业成员仍是当前快照、成交仍是日线开盘/触板代理或没有 Tick/L2，模型候选的 `simulation_eligible` 固定为 `false`。尾盘排序属于观察口径，一字/秒板和未知队列不得假定成交。
- `limit-up-forward-validation-v1` 是独立于历史代理的前向证据账本，只允许系统在有效交易时段真实保存的 live、非 stale 快照进入。20 日只检查采集和闭合流程，60 日后才复核策略；无合格快照或无闭合交易时收益字段必须为空，不能显示成 0% 策略。历史代理不得回填前向日期，Tick/L2 补齐前不得升级为模拟执行。
- 实时信号必须区分 `research_action` 和 `action`：历史负期望门先否决研究动作，战法验证门再把未验证动作降为 `pass`。严格前向观察读取 `research_action` 并明确标记“未执行研究动作”，普通动作回测只读 `action`；这样既能积累冻结后样本，也不能把观察记录伪装成真实推荐成交。
- 实时和无严格快照的历史代理可以读取 `result_date < signal_date` 的成熟同路径样本，但该证据只作风险否决：有效样本不少于 60 笔时，平均净收益非正、收缩胜率低于 40% 或硬亏损率不低于 20% 可把 `buy_now / next_auction` 降为 `pass`；正样本不能直接证明可交易。实时证据服务异常必须 fail-closed，禁止所有可执行动作；历史代理可以保留只读信号并标记数据质量错误。已保存的严格历史快照必须原样返回，不允许用后来形成的样本回填或改写当时动作。
- 公共涨停池的封板资金可以用于实时风险收紧，但不能冒充 L2 队列。只有间隔不超过 2 分钟的连续快照才累计封住时长和封单变化；相邻封单缩水超过 30% 时关闭买入动作。该字段从新快照开始进入严格前向账本，在形成新时间外样本前不能宣称提高了历史胜率。
- 实时快照是否保存由交易阶段、行情交易日、`mode=live_snapshot` 和 `is_stale=false` 共同决定。非交易时段刷新必须只读；行情源日期落后时不得保存。自动计划和手动“立即执行”必须走同一个 `limit_up_live_scan` 动作，未保存结果统一记为 `skipped`，不能显示成成功采集。
- 当前日期的 10 秒页面轮询固定读取 `/live`，历史日期固定读取 `/signals`。`/live` 只能读取后台以 15 秒目标间隔更新的快照，不得在 GET 内访问外部行情；同一分钟允许 upsert 同一审计行的最新内容，交易时段同日快照超过 90 秒未更新时必须 fail-closed。实时快照保存板块前二的完整雷达池，Top5 只负责推荐排序和最多 4 只组合，不能因未进 Top5 丢失盘中出现历史。AkShare 实时涨停池必须并行读取且每个 HTTP 请求有 8 秒硬超时，任何公共源不得无限占住扫描线程。显式采集和自动采集继续统一走 `limit_up_live_scan`，公共源轮询不能宣称具备 Tick/L2 的逐笔抢板能力。
- `/limit-up` 的模拟资格由 `limit-up-data-quality-v1` 的 8 个硬门禁统一控制：点时历史账本、涨停事件路径、逐日板块成员、个股分钟路径、竞价、板块分钟资金、Tick/L2 队列和 60 日真实前向观察。600 日日线账本只允许把研究账本标为就绪；当前成员快照、日终资金或日线价格代理不得让执行类门禁通过。任一必需门禁未达标时 `simulation_eligible` 固定为 `false`。
- 严格时点采集从新交易日起前向累积：09:26 保存竞价结果，每次盘中“即时”板块资金同步追加资金与涨跌扩散，19:00 成员重建成功后保存逐日成员版本。公共竞价源未提供未匹配量，因此即使已经保存价格和撮合量额也只能显示部分覆盖；不得把“表存在”或“已采集一天”解释为历史门禁完成，更不得据此宣称稳定复利。
- 历史涨停事件和开盘竞价允许通过 Tushare/完整 CSV 回补，但必须先和本地日线逐日核对完整度：事件至少 90%，竞价至少 95%，否则整日不写且保留旧数据。导入时间与行情时点分开保存；Tushare `stk_auction` 缺未匹配量，不能解除严格竞价或 Tick/L2 门禁。当前 Tushare token 未配置，CSV 预检查可用但没有因此产生任何历史写入。
- 同花顺公开 `limit_up_pool/open_limit_pool` 允许以后台批次回补近 252 个交易日的涨停/炸板路径，必须复用 90% 逐日完整度和原子替换规则；空响应、供应商错误或覆盖不足不得删除旧数据。2026-07-12 真实落库为 `2025-06-27..2026-07-10` 共 252 日、19,978 条，但该源不是 500 日全历史，也不含 Tick/L2 队列或完整竞价证据，`simulation_eligible` 继续为 `false`。
- 历史行业归属使用申万二级 `index_member_all` 区间，按 `in_date <= D < out_date` 展开；同股同日重叠时只选最新 `in_date` 并审计冲突。逐日写入前必须覆盖至少 90% 的当日有效主板日线股票，只替换 `sector_type=industry`，不得删除概念快照。历史账本优先读取日期快照，缺失才回退当前行业并保留幸存者风险标记。当前 Tushare token 未配置且未导入完整 CSV，四种历史成员日数仍为 0，不能因此解除模拟门禁。
- 涨停事件分钟补数与推荐股票池使用同一沪深主板非 ST/退市/特殊状态口径，创业板、科创板和北交所不进入事件总量、覆盖率或补数队列。只选择本地确实无 1 分钟数据的股票-日期对，固定补 `09:15-15:00` 整日路径；产品和夜间任务默认每批 200 个。产品必须走后台 `202 + batch_id + 2秒轮询`，不能让长批次占用同步 HTTP；全局无关批次返回 `409`，同一批次复用。`limit_up_minute_backfill_attempts` 独立保存 `covered / empty / error`、尝试次数和 1/3/14 天退避；TDX 空结果或错误不算覆盖。夜间任务固定在 21:30 正式量化之后，不能阻塞前面的日线和量化产物。
- 事件门禁和板块触板扩散都必须使用沪深主板非 ST 口径；盘中重复事件按 `vt_symbol + trade_date` 只取最后状态，休市日或没有同股同日日线的快照不计入覆盖，但原始记录保留审计。东方财富涨停/炸板池只用于近期恢复，2026-07-12 实测最早可用日为 2026-06-22，不能承担 500 日历史回补。供应商空响应不能删除已存在的可靠事件；严格全历史仍依赖 Tushare `limit_list_d` 或完整 CSV。
- `/mainline` 顶部情绪周期图是短线市场温度计，不是独立买卖策略。后端 `/api/mainline-replay/sentiment-cycle` 历史点只读完整 `stock_daily_bars`，盘中点只读 `stocks` 快照和 `stock_minute_bars` 高点作临时投影；指标包括情绪分、冰点/修复/分歧/高潮/退潮阶段、涨跌家数、涨跌停、日K高点触板未封的炸板代理、连板高度、昨日涨停今日继续涨停的晋级率和近 5/20/当前区间摘要。前端曲线支持鼠标指向交易日、点击锁定交易日明细，并在锁定后懒加载 20/60/120 日版本周期热度。炸板率和晋级率是本地可见代理，不等同逐笔封板/一进二/二进三专表。
- 用户界面和 API message 不暴露 `replay` 这类内部词；统一称为“买卖记录”或“买卖执行记录”。内部接口路径/表名可暂时保留兼容。
- 股票展示尽量使用“名称 + vt_symbol + 板块标签”，并复用可点击的股票身份组件。

## Strategy Rules

- 普通用户入口只公开 `mainline_dragon_pullback` 一个策略；旧策略只保留为内部兼容和旧报告对比。
- 策略优化不能设计成需要用户手动选择的开关。研究参数、实验开关只允许作为研发验证和回测隔离工具；产品落地必须表现为一个确定的默认策略版本，达标后合入默认，不达标就不进入默认。
- 候选生成和组合回测必须按历史逐日推进：D 日只使用当日及以前可见数据生成候选；候选质量主报告按 D 收盘价作为理论买入价，组合执行诊断仍另行处理 D+1 执行约束。
- `/quant` 当前产品质量主口径是 `candidate_trade_quality`：全历史交易日每日只评审 Top5/Top10/Top20，D 日 BUY 候选按 D 日收盘价买入，D+1 收盘收益作为主胜率和主收益；买点区域、金/银手指窗口、月份和重点区间都要用 Top5/10/20 分桶矩阵验收；D+2/D+3 是否值得格局只作为辅助标签。
- 候选观察默认评分前 `100`、分页 `20`；候选质量默认只汇总每日 Top5/Top10/Top20。观察前 `100` 方便审查排序，不等于扩大真实执行池。
- 不强行给低吸、龙回头或超跌反弹保留名额；候选按统一评分/内部 ranker 排序。
- `WATCH` 只表示观察，不进入自动组合买入。真实买入计划只来自 `action=BUY` 并通过组合约束的候选。
- `entry_signal` 是原始诊断字段；只有 `executable_entry_signal=true` / `action=BUY` 才显示为可买入、计入 BUY 次数并进入买入计划。
- 研究买点只用于解释和复盘：`research_entry_signal=true`、`signal_role=research_buy` 或 evidence 中 `*_entry_observation_only=true` 的点必须显示为观察/研究标记，不得生成真实交易段，不得进入组合执行池，不得计入正式 BUY 收益胜率。
- 用户可见候选读取必须匹配当前 `signal_evidence_schema_version`；旧 schema 不应静默回退展示旧解释字段。
- 同一交易日可能存在多次 `quant_signal_runs` 全量同步。所有候选 TopN、收益胜率和页面对比必须固定 run_id，或按“每个交易日最新成功 run_id”去重。

## Market And Setup Model

- 行情阶段 `主升 / 震荡 / 退潮 / 回暖`、金手指和银手指当前作为内部因子、风险上下文和用户解释，不直接作为用户策略开关。
- 低吸首启、龙回头、超跌反弹是内部 setup/候选源；支撑、均线承接、量能、收盘位置、风险形态是共用因子，但不能粗暴叠分。
- `bottom_reclaim/bottom_ma_repair` 是底部修复加分项和 reserve，不是独立 BUY，也不是简单过滤器。
- 公开游资/短线方法只能转成可验证代理，例如主线、情绪周期、分歧、承接、再转强、买点质量和卖点质量；不能量化为席位身份硬规则。
- 在历史板块/资金流覆盖不足前，不能宣称已经稳定量化科技主线或新主线轮动。
- `/mainline` 概念页 `continuation_status` 的"维持"必须是量价齐升：价格涨且主力非明确净流出。价格涨但主力净流出（顶部派发，如芯片半导体 +2.7% / -358 亿）必须判 `BROKEN`，不能 `MAINTAINED` 霸占榜首掩盖撤退；资金流缺失(None) 不等同流出，不降级。live 与历史回放（snapshot）均走派发：`_ranking_for_date` 已 LEFT JOIN `sector_fund_flows` 补 `main_net_inflow` + `data_mode="history"`，`_enrich_concept_index_context` 对有 `data_mode` 的 item（live/history）都走量价判定，只有 delta/无 data_mode 才回退 hot/cold。回归测试：`test_continuation_status_marks_top_distribution_as_broken`、`test_enrich_marks_history_distribution_as_broken`。

## Backtest And Baseline

- 当前产品基线和策略实验结论以 `memory/06_backtests/README.md` 和 `memory/06_backtests/strategy_optimization_ledger.md` 为准。
- `baseline_only=true` 只返回持久化组合回测基线；它不代表候选质量主口径。独立组合回测若用于执行诊断，必须与候选质量基线分开解读。
- BUY 信号不等于实际成交。BUY 代表 D 日收盘后生成候选/计划；真实组合成交另行经过 D+1 执行价、涨跌停、现金和组合上限等约束。
- 策略优化结论必须区分候选层和组合层：候选层按每日 Top5/Top10/Top20 的 D 收盘买入、D+1 收盘验证验收，组合层必须另跑真实组合回测。
- 信号只负责买点/拒买证据；卖点应按真实持仓、入场成本/支撑、最高浮盈回撤、当前支撑结构和当前日信号动态计算，且必须无未来函数。
- 后续优化优先做候选自身买点质量、统一 Top5/Top10/Top20 排序质量和 D+2/D+3 格局判断；真实组合执行只作为独立成交层复核，不回灌为候选质量解释。

## Single-stock Review

- 股票详情页主图口径是“当前公开策略对该股票独立全历史复盘”，不看组合最大持仓、不看组合是否真实持有。
- 股票详情固定使用 `mainline_dragon_pullback`，读取单股复盘结果；缓存缺失或落后时可后台创建同策略单股复盘缓存。
- 股票详情主 K 线只显示 `买入 / 拒买 / 卖出`：买入和卖出来自单股复盘成交路径，拒买只展示买入拒绝。
- 牛熊线是只读多指数潮汐层，映射到个股价格坐标展示 `线上/线下`、距离、方向和简短动作提示；它不自动改买点、卖点或资金权重。
- 完整 `signal-history` 只用于逐日评分审计、分数解释和诊断场景，不决定主图买卖点。
