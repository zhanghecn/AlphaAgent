# Decisions

这个文件记录仍然有效的长期决策。按日期产生的验证过程、接口输出和截图不放在这里；需要证据时链接到 `memory/06_backtests/`、`docs/plans/` 或具体源码。

## Project Boundary

- 项目外显名称是 AlphaAgent，目标是基于 vn.py 做服务端化 A 股量化研究、智能选股、策略回测、模拟持仓和后续交易工作流。
- 保留 Python 包名和源码目录 `vnpy`，不重命名为 AlphaAgent，避免破坏 vn.py 插件依赖和已有导入。
- 不修改继承的 `vnpy/` 核心包和官方 examples，除非用户明确要求或项目兼容性必须修改。
- AlphaAgent 自研业务层放在 `alphaagent/`、`frontend/`、`docs/`、`requirements/` 和 `memory/`。
- 需求分析和产品设计放在 `requirements/`，长期项目事实放在 `memory/`。

## Collaboration And Git

- 不主动 `git commit` 或 `git push`。只有用户明确要求“提交”或“push”时才执行。
- 工作区可能包含用户或前序模型改动，不能随意 revert、reset 或 checkout。
- 提交前优先做可验证的小步整理：编译、定向测试、前端 build、`git diff --check`。
- `memory/` 是项目地图，不是日记。新增事实时优先改写现有 overview，长报告放到 typed artifact。

## A-share Capability

- 当前 vn.py GUI 只注册 CTP，不能声称已经接入 A 股实盘或全 A 实时行情。
- A 股实盘交易应通过官方或兼容 Gateway，例如 XTP、TORA、OST、EMT。
- 历史数据应优先通过可验证的数据源或插件，例如 XT、RQData、Tushare、券商/QMT/TDX/vn.py 本地库。
- 免费公共分钟源只能作为近端补充，不能直接当作长区间严格回测依据。

## Gateway And Auth

- 部署统一入口是 Go 网关 `alphaagent-gateway`（`gateway/`，chi + golang-jwt），对外唯一端口；`alphaagent-api` 和 `alphaagent-web` 只 `expose` 内部端口，不再对外，杜绝绕过登录直连。
- 管理员账号密码登录：账号 `ADMIN_USERNAME`、密码 `ADMIN_PASSWORD` 从环境变量配置；首次部署 `deploy/docker-deploy.sh` 仍为占位值时自动随机生成并打印。密码用 SHA-256 + `crypto/subtle.ConstantTimeCompare` 常量时间比对，单管理员场景不引 bcrypt。
- 登录态用 JWT（HS256）放在 `Authorization: Bearer` 头，前端存 `localStorage`（key `alphaagent_token`）。取舍：无 CSRF、未来可扩展多端，但接受 localStorage 的 XSS 窃取风险（前端无 `dangerouslySetInnerHTML` 滥用）。这是当前选择，不是 cookie 方案。
- 网关登录端点不返回 401：`GET /api/auth/me` 返回 `{authenticated:false}`，前端路由守卫（`App.tsx` 的 `RequireAuth`）据此跳转，无需处理 401 异常分支。其余 `/api/*` 由 `middleware.Auth` 校验 token，失败返回 401，前端 `client.ts` 全局拦截 401 → 清 token + 跳 `/login`。
- 发版走 GitHub Actions（`.github/workflows/docker-release.yml`），推 `v*` tag 并行构建 `alphaagent-api/web/gateway` 推 `ghcr.io/zhanghecn/<name>:latest`。生产 compose 三个自研镜像 `pull_policy: always`，因此 `docker compose -f deploy/docker-compose.local.yml up -d` 一条命令即可拉最新镜像滚动发版。
- 当前先 HTTP 跑通（网关监听 80）。后续要 HTTPS 时在网关前加一层 Caddy 自动签证书，不要在网关里自己处理 TLS 终止。
- 走网关同源后前端 baseURL 是相对 `/api`（`frontend/docker-entrypoint.sh` 生成 `config.js`），后端 CORS 基本不触发；仍把 `allow_methods` 扩到 GET/POST/PATCH/PUT/DELETE/OPTIONS 兼容直连调试。
- 本地开发 = 预发布 = 正式版，三套环境完全同步：都用 `docker compose up`（本地 `docker-compose.yml` build 模式、生产 `deploy/docker-compose.local.yml` 预构建镜像模式，服务结构与网关架构一致）。本地 web 用 `target: runtime`（nginx serve dist，不再是 Vite dev server），入口统一 `http://localhost:8080` 网关；改前端后 `docker compose up -d --build alphaagent-web` 重建。不再保留 5173 dev server 或 api/web 端口直连的分裂开发模式（旧 `alphaagent-web-local`/`alphaagent-api-local` 容器已删除）。

## Quant Product Shape

- `/quant` 是量化研究工作台，主路径为一键策略研究、候选查看和组合回测归因。普通用户视图只保留“候选/回测”两个入口；数据质量、日志、分钟模型等只作为高级/内部复核能力，不放在普通主流程。
- `/portfolio` 是独立持仓模块，负责自选分组、量化候选分组、模拟持仓、成本价、买卖依据。
- 股票详情页 `/stocks/:vtSymbol` 承接单股回测、K 线买卖点、财报口径和组合回测复核。
- 量化页默认只展示组合回测；股票详情页生成的单股回测不混入量化页主列表。
- 股票展示尽量使用“名称 + vt_symbol + 板块标签”，并复用可点击的股票身份组件。
- 用户界面和 API message 不暴露 `replay` 这类内部工程词；统一称为“买卖记录”或“买卖执行记录”。接口路径、字段名和表名可先保持 `replay` 以避免兼容性迁移。

## Candidate And Strategy Rules

- 组合回测必须使用历史逐日动态候选：每个信号日只使用当日及以前可见数据生成候选，再在下一交易日执行。
- 前端只暴露“刷新候选并回测”主操作：页面调用 `POST /api/quant/research-runs` 创建后台研究任务并轮询状态；任务内部从用户选定交易日跑到本地最新交易日，自动补候选、生成买卖记录并运行组合回测。
- 候选区间生成是内部主量化过程；`persist=true` 时会跳过已存在成功交易日，只补缺失日期，并基于已落库 `quant_stock_signals` 生成统一 `strategy_replay_runs` / `strategy_replay_attempts`，不再让股票详情默认单独重算一套单股缓存。
- 量化页候选 tab 展示候选和自动回测状态，不再要求用户单独理解或手动触发“生成区间候选/生成执行复盘”。“产品口径”指展示、命名和业务解释口径收敛，不代表拆页面或新增复杂入口。
- 候选页不拆复杂多入口；低吸洗盘、龙回头、风险拒绝等都作为同一候选评分和解释字段展示。默认观察评分前 `100` 个候选并分页显示，每页 `20`；组合模拟默认最大持仓 `10`、执行 BUY 候选前 `20`。观察前 `100` 只方便用户审查评分排序，不会强行保留低吸名额，也不会扩大真实执行池。
- 候选评分必须可解释：候选行或股票复核中应能看到“为什么这个分数”，包括状态、低吸蓄势天数、均线收敛、低吸蓄势分、失败规则和评分拆解，避免用户只看到黑盒总分。
- 候选、股票详情、量化候选分组和组合执行 action 必须一致：`entry_signal` 是原始诊断字段，只有 `executable_entry_signal=true` / `action=BUY` 才显示为可买入、计入 BUY 次数并进入买入计划；硬信号低于 `min_entry_score` 或存在失败规则时展示 `WATCH`，不能显示为可买入的 `BUY`。
- 旧 `quant_recommendations.action` 不能单独作为当前候选 BUY/WATCH 依据。读侧必须从规范化后的 `reason/evidence` 重新派生当前 `action`、`signal_label` 和 `failed_rules`；如果旧落库 action 与当前派生 action 不一致，API 应保留 `persisted_action` 并标记 `action_mismatch_resolved=true`。例如旧缓存中 `002240.SZSE` `2026-03-13` 曾是 BUY，但当前证据是 `low_suction_launch_unconfirmed`，应显示为 `WATCH / 低吸蓄势观察`。
- 用户可见候选读取必须匹配当前 `signal_evidence_schema_version`；如果只有旧 schema 的候选 run，不应回退展示旧解释字段，而应提示刷新候选。组合回测可继续复用旧候选缓存以保持全历史速度，但读侧可以补只读诊断字段，不能改变历史分数或买卖。
- 量化页候选默认日期优先选择当前公开策略最新已生成候选日；如果最新交易日尚未运行，不应默认展示空候选误导用户。工作流卡片必须同时显示本地日线最新交易日和候选最新日期，明确暴露候选滞后。
- 量化页候选 KPI 使用当前选中交易日实际推荐数；分组同步数只作为同步状态，不作为“候选数量”主指标。
- 量化页组合回测列表按当前公开策略和当前注册版本过滤；旧策略或旧版本回测不能挤掉当前策略回测。
- 普通用户入口只公开 `mainline_dragon_pullback` 一个策略；策略仍通过注册表管理，避免在 API/UI 里硬编码散落。
- 旧 `mainline_leader_pullback`、`breakout_confirmation`、`limit_up_after_pullback`、`trend_acceleration` 只保留为内部兼容和旧报告/对比工具能力，不再出现在普通策略列表和主流程下拉中。
- `WATCH` 只表示观察，不应作为自动组合买入信号；买入计划只应来自 `action=BUY` 并通过组合约束的候选。
- 量化候选分组的 reason JSON 也必须同步 `action`、`raw_entry_signal`、`executable_entry_signal` 和 `failed_rules`，前端展示优先读 `action`，不能只看原始 `entry_signal`。
- 下一阶段回撤/排序优化计划见 `requirements/alphaagent_strategy_drawdown_optimization_plan.md`，当前只是执行计划而非已上线策略：信号只作为买点/拒买证据，卖点应以买点成本/支撑为锚，结合持仓最高浮盈回撤、当前支撑结构和当前日买入/持有状态动态计算；高位已有浮盈后从最高价突然回撤约 `7%` 应作为疑似出货的回撤止盈实验条件。高位横盘出货风险以 `603226.SSE` 为重点样本，初始按至少约 `15` 到 `20` 个交易日的高位窄幅横盘定义“横久”，但必须验证不误伤短期正常龙回头回踩。低吸涨停启动四因子作为待验证的低吸质量增强证据：近 `20` 日涨停/近涨停、`4`/`5` 连阳、上涨段向上跳空缺口、持续倍量/放量；只有证明能提高弱市/震荡市低吸胜率后才可加小额排序分。候选展示只显示选中的买点、拒买和卖出，不展示密集观察日流。
- 买后三个可见持仓日仍无启动可以作为路径审计标签，但不能默认做早退卖点。`#201` 已验证 broad `failed_launch_exit_stop` 会改变组合路径、错过趋势大赢家且没有降低 `support_stop` 总损失；`#211` 的替换质量保护版 `enable_contextual_failed_launch_exit_stop` 保住了趋势赢家并把最大回撤从约 `-15.59%` 小幅改善到 `-15.53%`，但收益从约 `+82.99%` 降到 `+82.56%`，直接触发只有 `1` 次，且没有修复 `601179.SSE`、`600352.SSE`、`002240.SZSE`、`002443.SZSE`、`002119.SZSE` 等重点失败路径。结论是失败启动早退仍只能作为默认关闭实验/审计方向，不能默认开启。后续若继续做失败启动，必须先增强失败启动分类器，并叠加市场/板块环境、reclaim 失败和替换质量保护。
- 低吸“没拉起来直接卖”的产品语义已经校正：它不是等待三天后卖，而是买后立即无承接、破关键支撑/均线且无法 reclaim 时直接控制风险。候选级复核显示，粗糙 `direct_close/direct_next_open` 和盘中 `-3%/-5%` 止损代理虽然能降低 MAE，但会降低胜率、平均收益和中位数；这只是内部压力测试，不是用户提出的完整规则。更清晰的独立结论是：stricter `balanced_first_lift` 等待 MA10 三日回踩入场，胜率约 `55.74%`、平均约 `+3.14%`，优于 D+1 开盘的 `51.61%`、`+2.06%`。因此默认策略不得上线 broad 快撤或简单直接止损；下一步优先做默认关闭的低吸 MA10 回踩入场实验，并继续研究更窄的失败启动分类器，条件至少应包含 reclaim 失败、市场/板块退潮、弱收盘/弱量和替换质量。
- `support_stop` 后反弹可以作为只读审计方向，但不能默认改成“支撑止损先不卖”。`#194` 反弹组确实有更高 early/path MFE 和更大的卖出信号日恐慌振幅，但可见特征的简单分类器精度不足。`rebound_prone_support_stop_review` 已作为路径诊断只读标记实现；它只能帮助定位疑似卖早样本，不参与买卖、排序或仓位。后续交易实验必须结合 market/sector context、reclaim 条件和替换质量保护。
- 公开游资/短线方法只能转成可验证代理，不作为身份或席位硬规则。后续研究重点是主线/情绪周期、强弱、分歧、承接、再转强和替换质量；在历史板块主线数据不足前，只能作为审计标记和实验假设，不能宣称已量化“科技主线”或“某游资打法”。
- `主升/震荡/退潮/回暖` 行情阶段先作为只读审计和用户解释，不直接进入默认评分、排序、买卖、卖点或仓位。`#203` 四象限审计显示候选 top20 在主升阶段质量不差，但真实成交主升样本表现弱；因此下一步优先排查候选到真实成交、满仓换仓、持仓保护和卖点替换质量，而不是直接做“主升加分/加仓”或“退潮空仓”的宽泛规则。证据见 `memory/06_backtests/2026-06-20_market_phase_audit_experiment.md`。
- 行情和策略族的最终整合口径已写入 `requirements/alphaagent_phase_strategy_integration_plan.md`，第一版全局证据见 `memory/06_backtests/2026-06-21_phase_strategy_family_matrix.md`，重点股票组合路径证据见 `memory/06_backtests/2026-06-21_focus_symbol_path_matrix.md`，独立单股 replay 证据见 `memory/06_backtests/2026-06-21_single_stock_replay_matrix.md`：行情层不直接和个股买点分数相加，而是作为环境层、风险预算和策略族选择器；内部把 `低吸首启` 与 `龙回头` 分开建模，执行层再处理候选排名、最多 10 持仓、执行前 20、满仓替换和卖点。普通用户仍只看到一个公开策略和简单的 `买入 / 观察 / 拒买 / 卖出`，可以用高级过滤查看 `低吸首启 / 龙回头 / 冲突`，但不需要手动切换多个策略。`#203` 矩阵已证明：`低吸蓄势` 不应每天画 BUY，`龙回头+低吸` 重叠不能自动叠分，主升候选质量好但真实成交差说明瓶颈在执行/替换/卖点。17 个重点股单股 replay 已补齐，证明多数重点股单股路径为正，贵州三力和剑桥科技是真正单股策略失败样本；组合层仍要查满仓、替换、卖点和展示链路。剩余缺口是默认关闭组合实验和 UI 接入。不能继续把零散因子直接塞进默认策略。
- 候选到真实组合的满仓机会审计已经明确：Top20 候选中真实新标的满仓错过并不整体优质，`#203` 的 `314` 条新标的满仓错过 20 日后验均值仅约 `+0.21%`、中位数约 `-1.67%`。因此不能默认开启宽泛换仓或简单扩大执行池；下一步只能研究高价值错过机会的信号日可见代理特征，例如强启动/主线/支撑失败组合、弱持仓状态和更严格替换质量。新增 `portfolio_opportunity_summary` 只读字段用于 `/quant` 回测分析，不参与评分、排序、买卖、卖点或仓位。证据见 `memory/06_backtests/2026-06-20_candidate_to_portfolio_opportunity_audit.md`。
- 多策略行情适配也先做只读评审：`POST /api/backtests/strategy-comparison` 的 `phase_summary` 用同一参数非持久化重跑策略，并按真实闭合成交买入日的可见行情上下文聚合 `主升/震荡/退潮/回暖`；`candidate_phase_summary` 从理论 BUY signal events 的执行池 Top-N 上下文聚合候选质量，用于区分“候选本身在某行情变差”还是“真实组合持仓/卖点/换仓拖累收益”。`/quant` 只展示矩阵和适配提示，不自动推荐切换策略、加仓或空仓。这些字段都标记 `not_used_for_signal_score=true`，不能作为默认交易规则；更完整的候选快照审计仍可后续单独做持久化或专门接口。

## Backtest Execution

- 普通新建组合回测默认执行模型是 `legacy_next_open / strict_entry=true`：D 日收盘产生信号，D+1 按日线开盘价执行买入和卖出。
- `baseline_only=true` 只返回产品默认基线：当前公开策略、结束到最新本地交易日、默认研究参数且未标记 `exclude_from_product_baseline`。如果同结束日存在多个默认参数起点，读侧优先使用显式 `baseline_policy=current_product`；没有显式标记时，按同结束日中最常见完整起点选择，并通过 `baseline_warning` 暴露更长起点样本。局部候选刷新、短区间诊断或研究开关回测必须显式排除，不能顶掉 `/quant` 和股票详情默认基线。
- 历史主流程不再依赖 `14:30` 分钟线。14:30/分钟快照只保留为未来实时数据、盘中确认、分钟数据同步和旧报告兼容能力。
- BUY 信号不等于实际购买。BUY 信号表示 T 日收盘后策略生成买入计划；实际购买必须经过 T+1 执行价、涨停/跌停、现金和仓位等约束。
- `mainline_dragon_pullback` 组合满仓时允许有限换仓：只有 `total_score >= 98` 的新鲜 `TAIL_BUY_READY` BUY，才可替换浮盈不超过 `+3%`、持有不少于 `3` 天且入场分不高于新信号的持仓；默认最大持仓仍是 `10`。
- 执行拒绝原因必须精确区分：`limit_up_open_blocked` 是开盘涨停买不到，`limit_down_open_blocked` 是开盘跌停卖不出，`no_execute_bar` 是缺执行日 K 线，不能再合并成“涨停或缺数据”。
- `tail_close_hybrid` 和 `strict_1430` 保留为研究对比/旧报告兼容模型，不能当作当前历史主流程。
- `strategy_version < 0.1.1` 只作为旧报告兼容，旧绩效不作为当前策略结论。

## Single-stock Review

- 股票详情页主图口径固定为“当前公开策略对该股票独立全历史复盘”。它不看候选排序、不看组合最大持仓、不看组合是否真实持有，也不再提供 `交易复盘 / 候选信号` 切换。
- 股票详情页固定使用公开策略 `mainline_dragon_pullback`，读取 `/backtests/symbols/{vt_symbol}/latest` 和 `/backtests/{id}/audit` 的单股复盘结果。没有单股缓存、缓存起点晚于 `2025-03-26` 或缓存终点早于最新本地可用交易日时，页面自动后台创建同策略单股复盘缓存。
- 股票详情页主 K 线只显示单股复盘得到的 `买入 / 拒买 / 卖出`：买入和卖出来自单股复盘成交路径，拒买只展示买入拒绝；卖出拒绝等内部执行噪音不进入主图三类标记。
- 股票详情页仍读取最近全局量化状态；牛熊线首屏读取轻量 `GET /api/quant/symbols/{vt_symbol}/market-line`。完整 `signal-history` 只用于逐日评分审计、分数解释和诊断场景，不决定主图买卖点，也不再作为详情页牛熊线首屏依赖。
- 牛熊线是只读多指数潮汐层，按 `主升 / 震荡 / 退潮 / 回暖` 展示当前行情；它使用当日及以前可见的指数、广度、风格和资金上下文，不进入默认策略评分、买卖或仓位。股票详情首屏必须走轻量 market-line 接口，避免为了展示行情线触发逐日个股评分和完整审计大响应。
- 股票详情 K 线中的牛熊线必须映射到个股价格坐标，作为行情风险阈值线展示。图例显示个股相对牛熊线的 `线上/线下`、距离、牛熊线方向和简短动作提示；例如个股在线下且线下行时以空仓/防守为优先。该提示仍是只读解释，不自动改买点、卖点或仓位。
- 退潮阶段的牛熊线方向优先服从行情阶段，不被个股 EMA20 抬升误判为上行。退潮且个股跌破 MA5 或大阴低收时，线位应抬到 MA5/MA10 一类短线风险门槛，用于提示空仓/防守；该规则仍只属于股票详情展示层。
- 最新组合回测逐股详情只作为“组合回测参考”辅助展示，用来解释组合里是否因为名额、换仓、资金或执行约束产生不同路径；它不能覆盖股票详情主图的单股策略复盘。
- 股票详情页的实际订单/成交 raw 必须保留或读侧补足入场 evidence。旧持久化订单若有 `entry_setup`、`low_suction_days`、`ma_convergence_pct`、`latest_change_pct`、`close_location_in_range` 等可见字段，可只读派生 `early_dragon_pullback_risk` 供解释；该字段是诊断标签，不参与分数、买卖、排序或收益计算。
- 股票详情页会抑制已关联真实成交订单的同回测理论 BUY 标记，避免同一信号同时显示“信号”和“买”两条重复标记；仍保留没有真实成交的理论信号用于解释历史机会。
- 候选追踪、理论信号计划、真实组合订单/成交和单股复盘必须分清：股票详情主图只回答“这只股票按当前策略一路走下来会在哪里买、哪里拒买、哪里卖、收益多少”；候选页回答“某天全市场候选排序”；组合回测回答“最多 10 只持仓和换仓约束下实际会买什么”。
- 股票详情页 K 线普通展示已收敛为 `买入 / 拒买 / 卖出` 三类标记，并叠加只读“牛熊线”。页面统计按最终单股复盘标记重新汇总收益、胜率和闭合交易数。当前限制：页面可按主图买卖价计算闭合收益，逐笔持仓期最大回撤最好继续由后端单股复盘 audit/metrics 提供。
- 持仓中心的持仓卡读取 `/api/quant/symbols/{vt_symbol}/replay/latest` 派生策略建议，显示“策略持有 / 策略已卖出 / 卖出待确认 / 买入未成交 / 无买卖记录”等状态；后续如持仓数量变大再加批量买卖记录 API。
- 持仓中心不再把模拟账户金额作为用户主功能暴露；批量建仓、手动加入和加仓按股数/最小整手操作，KPI 和卡片以收益率、价格、股数和策略建议为主，持仓收益率按持仓股票收益率做算术平均，不再用市值金额加权展示。
- 股票详情页单股复盘不展示模拟账户金额，不以 `initial_cash/final_equity/cash/equity/amount/fee/pnl amount/volume` 解释单股收益。
- 单股收益率按闭合成交价格直接计算：单笔收益率为 `sell_price / buy_price - 1`，累计收益率为各闭合单笔收益率连乘。
- K 线图必须同时显示可执行 BUY 信号、买入拒绝、买入成交和卖出成交；即使本轮买卖记录没有 execution attempt，只要 `quant_stock_signals` 存在 `action=BUY` / `executable_entry_signal=true` 也要显示信号标记。原始 `entry_signal=true` 但 failed_rules 未通过时只作为 WATCH/买拒解释，不画 BUY 信号。点击 K 线或指标柱显示当日涨跌、跳空、振幅、均线距离、量比和相关信号/执行标记。

## Data Rules

- `/data` 普通入口默认是“尾盘准备”，只展示关键数据状态、自动计划、最近策略研究和 `立即尾盘准备/刷新状态` 两个操作。cron、job_ids、单任务执行、分钟缺口参数和执行记录属于 `高级同步`，默认折叠，不作为普通用户主流程。
- `/api/data-sync/tail-workflow` 是状态接口，只返回最新策略研究摘要、候选日期、尾盘预览缓存和定时计划；不能返回 `screen_run.items` 这类全量候选明细，候选明细必须走 `/api/quant/recommendations`。
- 尾盘自动化口径：工作日 `14:00` 跑 `tail_preview_14h`，`14:30` 跑 `tail_quant_1430`；两者都同步股票快照、分钟线、资金、热度和涨停池，并生成当天 `quant_tail_preview_cache`。旧 `intraday_14h` 和 `tail_prepare_14h` 禁用。`18:00` 跑 `eod_18h` 补完整日线、板块、龙虎榜、公告和财报等盘后真实数据。历史候选和组合回测仍使用完整 `stock_daily_bars`；今日尾盘预览独立走 `/api/quant/tail-preview`，默认读取当天缓存，没有缓存才用完整日线叠加今日分钟线/快照临时 Bar 现场只读计算，不写历史日线、`quant_signal_runs` 或量化候选组合。
- 18:00 盘后同步后续需要拆分快慢任务：股票清单和股票日线是必要收盘数据；板块历史 K 线、全板块成分、公告、财报等慢数据可夜间跑，避免盘后批次长时间停在 `running`。当前 `sync_sector_daily_bars` 默认只拉核心 `300` 个板块并输出进度。
- 回测评分只使用 `publish_date <= trade_date` 的财报，股票详情看到的当前财报不等于历史回测当天可用。
- 股票日线成交额入库单位必须统一为元；旧数据缺成交额时可用 `close * volume * 100` 估算流动性。
- 分钟数据补数属于实时/分钟数据层，不是历史策略研究主流程；如需旧严格分钟报告或未来盘中确认，应优先走同步/导入服务：`sync_stock_minute_bars mode=backtest_gaps`、TDX、Tushare、vn.py 本地库或供应商数据。
- CSV/file_path 是外部供应商回填和高级兜底，不是首选日常补数方式。
- API 必须区分日线开盘执行、实时分钟执行、收盘代理、缺快照、入场未触发和涨跌停/现金/仓位拒单。

## Current Strategy Evidence

- `requirements/alphaagent_pullback_low_suction_strategy_research.md` 已更新为当前回踩低吸优化研究结论：普通产品入口只公开 `mainline_dragon_pullback / 0.1.21`，低吸洗盘和龙回头在同一公开策略内作为内部 setup，不拆 UI，也不把低吸洗盘简单作为龙回头原始信号加分项。
- `mainline_dragon_pullback / 0.1.21` 是当前普通历史研究唯一公开策略代码；旧 `mainline_leader_pullback / 0.1.1` 和 `mainline_dragon_pullback / 0.1.0/0.1.1/0.1.3/0.1.6/0.1.8/0.1.9/0.1.11/0.1.14/0.1.15/0.1.16/0.1.17/0.1.18` 保留为内部备份/历史对照。
- `0.1.21` 保留低吸洗盘识别和严格执行线，但取消低吸固定保留名额。低吸天数可在 MA5/MA10/MA20 承接、缩量、MA20 未破、回撤受控和 MA 收敛改善时累计；至少 3 天吸筹后的首个温和拉升可确认 `stealth_low_suction`。低吸不再被经典龙回头的 `pullback_too_late` 硬压制，但派发、MA20 破位、回撤过深、过热、流动性和风险分仍是硬风险。
- 低吸涨停启动四因子已实现为诊断和审计字段，不能直接作为默认买入加分。`#190/#175` 审计显示 `stealth_low_suction` 闭合交易 `83` 笔中，`3-4` 因子桶胜率约 `28.57%`，未优于 `0-1` 因子桶约 `30.77%`；赢家平均因子数 `1.92`，输家 `2.02`。连续上涨标签上有弱正相关，`3-4` 因子桶 MFE>=8% 约 `42.86%`，高于 `0-1` 的 `30.77%`，但弱/震荡市场里 `3-4` 因子桶胜率仅约 `13.33%`。结论见 `memory/06_backtests/2026-06-18_low_suction_start_factor_audit.md`。
- 低吸启动确认和中段浮盈回撤止盈目前只是研究开关，不是默认策略：`require_low_suction_launch_confirmation=false`、`enable_mid_profit_giveback_stop=false`。完整组合实验已完成并拒绝默认开启：`#195` 中段浮盈回撤止盈收益约 `+56.10%`，`#196` 低吸启动确认硬门槛收益约 `+65.69%`，`#197` 两者同时开启收益约 `+74.44%`，均弱于 `#194` 约 `+82.99%`。结论是低吸启动确认可做排序/解释因子，不可做硬门槛；中段浮盈回撤止盈需要叠加失败反抽、大盘/主题走弱等上下文，不能只按最高浮盈回撤阈值卖。
- 启动质量和启动风险目前也只是研究开关，不是默认策略：`enable_entry_launch_quality_score=false`、`enable_entry_launch_risk_penalty=false`。`#199` 宽泛启动质量加分收益约 `+28.70%`，`#200` 窄启动风险处罚收益约 `+38.14%`，均明显弱于 `#194` 约 `+82.99%`。`#200` 没有降低 failed-launch 比例，反而扩大 `support_stop` 亏损并错过趋势大肉；后续只能把这些字段作为审计/解释，不能用孤立加分或扣分默认改排序。
- 顶分型、毛刺剧烈震荡、高位放量滞涨、关键支撑破位、成交极度萎靡和高位久横派发已先实现为 `mainline_dragon_pullback` 的风险证据字段。当前默认只把关键支撑破位和明确高位放量滞涨纳入失败规则；周线顶分型、毛刺自玩、低流动性遗忘、高位久横等先作为诊断/扣分，不得在未跑全局回测前宣称能提升收益或胜率。
- 低吸执行/换仓实验边界：`0.1.12/#162` 的 top20 外低吸补充执行池收益仅约 `+30.19%`，拒绝；`0.1.13/#163` 执行前 20 内低吸替换低效持仓可把回撤降到约 `-16.71%`，但收益降到约 `+46.88%`，拒绝作为当前基线；`0.1.15/#165` 收益约 `+55.41%`、最大回撤约 `-21.17%`，低吸覆盖改善但收益下降；`0.1.16/#167` 收益约 `+28.80%`，过度保守；`0.1.17/#168` 收益约 `+39.16%`、最大回撤约 `-27.63%`，低吸机会加分过宽；`0.1.18/#169/#172` 是上一版稳健基线。当前 `0.1.21/#194` 收益约 `+82.99%`、最大回撤约 `-15.59%`，作为当前运行证据。
- 卖出侧买入当天硬破位次日撤退实验 `0.1.20/#174` 已拒绝并撤回：同区间收益约 `+51.51%`、最大回撤约 `-19.00%`，最大回撤只微幅改善但收益、profit factor 和 Sharpe 明显弱于 `0.1.18/#169`。它释放仓位后引入更多低质量交易，并错过部分趋势大肉票；不应继续用“日线买后立即失败就统一早卖”作为默认规则。
- 卖出侧早期连续破位止损实验 `0.1.19/#173` 已拒绝并撤回：同区间收益约 `+54.40%`、最大回撤约 `-19.79%`，弱于 `0.1.18/#169`。它把 `support_stop` 亏损拆成更早的 `early_breakdown_stop`，但同时减少趋势大肉票收益；日线 D+1 下许多大亏来自隔夜跳空，不应重复用宽泛早期破位止损作为默认规则。
- 用户展示口径：量化页不拆成多个主流程，用户主操作仍是“刷新候选并回测”；候选页按评分展示观察前 `100` 并分页，组合执行 BUY 前 `20`，最大持仓 `10`。低吸洗盘、龙回头、均线承接、资金热度和风险破位都是同一候选评分的分数来源、扣分项和拒买原因，“为什么这个分数”直接显示在候选表和股票详情复核里。
- 单股低吸排查必须分清三层：`raw_entry_signal` 是策略形态成立，`executable_entry_signal/action=BUY` 是通过当前产品执行线，组合订单/成交还要通过排名、最大持仓和换仓规则。单股逐日看 `GET /api/quant/symbols/{vt_symbol}/signal-history`，组合没买原因看 `GET /api/backtests/{id}/candidate-trace?vt_symbol=&signal_date=`。
- 回测里的“信号计划”只作为买卖计划复核表展示日期、股票、方向、价格、评分、订单状态和原因；不再让用户输入或查看总资金、每笔预算、预览金额和预览盈亏。
- 普通 `/quant` 回测页不再把“信号计划”作为独立 tab 暴露；买卖信号到订单链路通过候选行“回测成交”和股票详情 K 线解释，避免普通用户理解一套额外流程。
- 普通 `/quant` 回测归因优先展示收益率、买卖日期、买卖价格、最大浮盈/浮亏比例、拒单/卖出原因和持仓天数；现金、总权益、买入占用、卖出回款、仓位金额等资金账本细节不作为普通用户主视图。
- `/quant` 回测首屏必须优先可见。年度分段、市场环境分段和前10候选审计属于默认可见的策略真实性证据，不能只藏在“验证”页；前10审计必须同时展示排除强势行情后的胜率/收益，避免科技牛市样本掩盖过拟合。前10审计需要区分“真实组合成交并闭仓胜率”和“固定20个交易日候选观察胜率”，后者只用于候选质量审计，不能参与策略买卖逻辑。数据质量、成本压力、随机样本、参数网格等更重分析仍放在验证区或后台加载，不能阻塞主要成交和收益归因。

- `support_stop` 下一轮实验优先级不是“浮盈回撤止盈优先”。只读理论空间估算显示：止损后反弹和真失败启动止损的空间更大，干净浮盈回吐只有 `13` 笔。`path-diagnostics` 已提供 replacement-quality attribution，用真实成交顺序把卖出和后续替换 BUY 配对，用于审计释放仓位后的替代交易质量。后续如写实验开关，必须默认关闭，并同时检查总收益、最大回撤、趋势大肉是否被截断、替代交易质量，以及分年份/分大盘环境表现。
- 每次策略优化必须维护 `memory/06_backtests/strategy_optimization_ledger.md`，记录版本、规则变化、回测编号、区间、收益、回撤、交易数、是否保留、未来函数/过拟合风险和证据文件，避免只靠零散报告比较。
- 全局买卖记录和股票详情必须把入场 evidence 传给卖出状态机。单股 replay 的 `Position.reason` 应与组合回测入场 reason 同构，至少包含 `support_price`、`max_drawdown_60d`、均线和评分证据；否则股票详情会出现比组合回测更晚的支撑止损，导致用户看到不一致的卖出标记。
- 组合轮动必须执行分差约束：只有新候选分数至少高出旧持仓 `rotation_min_score_gap` 才允许换仓。此前参数存在但未生效，导致低分差过度换仓。当前代码已修复，默认分差 `8.0`。
- 已验证不要用宽泛“高位均线发散无低吸”规则直接拒买：临时 `0.1.9/#145` 把收益从 `#147` 的约 `+59.27%` 降到约 `+45.52%`，说明会误杀强势二波机会。后续必须做更窄的失败形态验证。
