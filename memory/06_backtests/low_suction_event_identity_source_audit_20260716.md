# Low-suction Event Identity Source Audit - 2026-07-16

## Conclusion

本地涨停原因、打板概念强度和板块资金数据都不能替代低吸所需的历史点时概念成员，
也不能独立定义“每个概念指数的完整 Top3”。正式 Top3 阶段继续阻断，胜率、现金复利
和最大回撤仍为 `null`。

这些数据并非无用。涨停原因具有真实事件日期，可在严格成员到位后作为
`strong_day_count_cycle`、`sessions_since_strong` 和概念市场关注度的辅助特征；板块资金
中的“最大净流入股票”也只能作为单个市场认可特征。它们不能成为成员分母，不能用来
补齐未出现的股票，更不能把当前成员回填到历史。

6 月 15 日，而首个严格前向成员源日是 7 月 16 日，两者没有同日交集，无法做严格精度
校验。

## Why It Cannot Define Top3

1. 涨停原因只覆盖涨停样本；未涨停但相对强、成交额大或已成为趋势核心的成员完全缺失。
2. 28.4981% 的涨停事件没有原因，炸板事件全部没有概念原因，候选缺失不是随机缺失。
3. 原因短语是事件叙事，不保证等于东方财富指数成员关系；一个短语可能只是当天催化。
4. 同日达到 3 只候选的概念日只有 536 个，无法覆盖每个合格主升概念的 Top3 分母。
5. 用 7 月当前成员补洞会重新引入 V2 明确禁止的历史幸存偏差。

因此，事件原因最多能回答“市场当天把哪些强势股票归因到什么题材”，不能回答“当日
该概念有哪些成员，以及所有成员中谁排前三”。

## Public-source Check

- 东方财富 `push2` 和 AkShare 当前成员函数没有历史日期参数；附加日期不能证明历史成员。
- Tushare `dc_member` 仍是唯一已确认的同一 `BKxxxx.DC` 历史成员候选，但需要 6,000
  积分并且尚未实测三年完整性。
- XT/QMT `stocklistchange` 支持历史变化，但使用自身 `BKZS` 指数体系，本机也没有 QMT
  数据环境；不能与当前东方财富 BK 指数直接拼接。
- 本轮仍未找到零门槛、带日期、完整分页且使用东方财富 BK ID 的三年历史成员来源。

## Research Decision

1. 不用原因文本、资金最大股或打板候选冒充历史成员或 Top3 分母。
2. 保留原因关系作为严格成员到位后的市场认可辅助特征，证据 known-at 最早只能从事件
   日收盘后开始，供下一交易日使用。
3. 若做事件认可型开发筛查，必须单独标为 `event_recognition_falsification`，只用于否定
   明显无效的低吸方向；不得称为完整 Top3，不得读取锁定留出或发布正式绩效。
4. 免费前向成员/证券继续按 D-1 合同积累；首个源日 `2026-07-16` 只供下一可靠交易日
   使用，不回填过去。
