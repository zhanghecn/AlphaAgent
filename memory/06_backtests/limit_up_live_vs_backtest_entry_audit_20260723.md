## 为什么用户只看到涨停买点

2026-07-23 `10:00:00..10:44:59` 的运行库证据：

| 数据层 | 行数 | 10:00 后首条 |
| --- | ---: | --- |
| 内部 live trace | 499 | 10:00:01 |
| 内部 radar frame | 249 | 10:00:03 |
| 公开 signal snapshot | 0 | 10:45:39 |

内部扫描和买点已经存在，但旧调用顺序把公开 `save_snapshot()` 放在慢研究评分之后；用户只能
读到评分结束后的晚点快照。当前顺序已经改为：

```text
正式 v15 计算 -> 公开快照先保存 -> 本地分钟概率评分 -> 同分钟概率字段增强
```

此外，7 月 23 日上午最后一帧为 `11:30:55`，下午第一帧为 `13:20:38`。联环药业在
13:04 已触板时没有任何实时输入，任何排序算法都不可能生成提示。旧实时评分还会同步等待
逐股分钟/逐笔网络回填；当前主扫描已移除这些网络等待，只使用已完成分钟缓冲，缺失就观察。
该改动消除了已确认的阻塞路径，但部署后尚未经历新的完整交易日，实际最大帧间隔仍需由
后续自动账本验证，不能把代码测试写成前向实盘证据。

## 结论

1. “扫板买点被板前层删掉”已修复：正式首板扫板、回封和二进三均保留。
2. “研究评分结束前页面没有正式买点”已修复：正式快照先保存，逐股网络回填退出主扫描。
3. “全量实时列表受两仓限制”已修复：全量正式推荐不限数量，但首板统一执行回测盈利门。
4. “实时全量买点等于回测 62% 胜率”仍不成立。只有后来实际触板的身份与触板基线目标一致；
   实时板前误报和涨停价排队成交仍是独立风险。
5. 7 月 23 日 7 只正式触板票的 D+1 收益尚未形成；概率 TopK 也因当日特征行缺失不能评估。
   当前可靠成果是恢复及时公开正式 v15，并开始用同一合同积累可审计的板前前向数据。
