## 巨人网络复核

- `002558.SZSE` 巨人网络在 `10:31:57` 已涨 `+6.604%`，直到 `10:51:58` 都有接近涨停
  的保存快照；实际首次封板和正式 `buy_now` 都是 `10:53:18`。
- 当时保存的 `10:31:57` v2 信号已经是 `qualified_waiting_trigger`，但
  `public_quality_touch_ready` 是空值而非真值；板前榜要求该字段严格为真，所以实际页面
  没有展示它。这是旧运行帧的直接事实。
- 用当前代码复算同一份未触板原始信号时，因没有 `signal_time` / `buy_time`，公共质量门会
  把空时间解析成 `00:00:00`，判为 `B_recognition_only_outside_entry_window`。只注入当前
  快照时刻后，结果变为 `qualified_waiting_trigger` 且 `touch_ready=true`。这说明旧帧的空值
  与当前代码的时间门缺口指向同一个根因：板前评估没有可用的假设触板时点。
- 只把当时快照时间作为“若此刻触板”的反事实时间输入，不改变任何质量字段，结果从
  `10:31:57` 开始满足板前条件，至真实触板提前约 `21 分 20 秒`。这证明缺口是时间字段
  传递，而不是巨人网络不符合 A/B/C 质量。

## Root Cause, Fix, And Verification

`core_quality.quality_entry_gate()` 只从 `buy_time` / `signal_time` / 已发生的触板时间读取
入场时点。普通未触板实时首板没有这些字段，时间门便读成 `00:00:00`；而板前榜又要求
`public_quality_touch_ready=True`。两者组合使本应观察的候选被排除。

修复已部署到本地 `alphaagent-api` 和实时扫描 worker：仅对“未触板、没有任何已观察到的
触板/买入时刻、且状态为 `near_limit`”的信号，在调用同一公共 A/B/C 质量门时传入当前
快照时刻作为临时评估输入。它不会写回 `signal_time`、`buy_time` 或
`trigger_observed`；真实触板后仍使用真实首触/回封时间重新运行相同质量门。

部署后用数据库中巨人网络的原始快照回放：`10:31:57` 得到板前候选，
`trigger_observed=false`、`buy_time=None`；触板后的保存帧得到正式可买，真实买入时刻来自
实际触板事件，且不再属于板前候选。新增回归覆盖 B 级 `10:30` 边界和早触未回封保护；相关
测试共 `167` 项通过。市场已收盘，修复后的自然页面帧仍须从下一交易日开始审计。
