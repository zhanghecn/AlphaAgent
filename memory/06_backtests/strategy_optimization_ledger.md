## Current Logic

- Keep one public strategy: `mainline_dragon_pullback`.
- Do not expose low-suction and dragon-pullback as ordinary user strategy switches.
- Do not ship strategy optimization as user-facing switches. Research switches/params are internal validation tools only; a successful optimization must be merged into one deterministic default strategy version, and a failed optimization must stay out of the product path.
- Market phase `主升 / 震荡 / 退潮 / 回暖` is audit/risk context only for now. It does not directly change score, rank, buy, sell, or capital weight.
- `低吸蓄势` is not automatically a daily BUY, but the default product does allow high-score, no-hard-risk low-suction buildup to remain executable. `low_suction_launch_confirmed=false` is a quality/stage label by default; it becomes a hard WATCH gate only when the explicit `require_low_suction_launch_confirmation` research switch is enabled. Confirmed low-suction launch, including tightly constrained strong-launch days after mature low-suction buildup, is now a small default score/ranking bonus only (`+1.2`, or `+1.6` for balanced first lift), not a buy-eligibility gate.
- `低吸首启` and `龙回头` are separate internal setup families. They share support/MA/volume/close-location features, but overlap does not auto-stack score.
- Stock detail markers are independent single-stock strategy replay markers: `买入 / 拒买 / 卖出`. They do not read transaction-layer holdings or slot availability.
- Candidate independent trade quality report is read-only: every D-day BUY candidate is one independent sample, bought at D+1 open and exited by current sell logic. It does not enter default signal score, buy/sell rules, or any transaction-layer admission rule.
- Candidate independent trade quality uses a no-future entry rule: each sample uses its own D-day visible BUY as the entry signal, not a later higher-score/confirmed signal.
- Persisted no-cache portfolio runs now write `backtest_daily_candidates` factor snapshots directly. Candidate quality must use these snapshots when present; `backtest_signal_events` is only a legacy fallback because it is generated by a theoretical position state machine and can be affected by sell-path changes.
- Candidate quality APIs expose the current unit as `sample_count` / `daily_candidate_trade_count`; legacy `cluster_count` fields are compatibility aliases only.
- Candidate TopN quality must be read as candidate-pool quality, not a portfolio equity curve: Top10 means every historical signal day's ranks `1..10` are each simulated independently; Top20 means ranks `1..20` cumulatively. The separate rank-window table (`1-10 / 11-20 / 21-50 / 51-100`) shows marginal quality by daily rank band, and the signal-day table shows one trading day's Top10/Top20 outcomes.
- Unified strategy acceptance uses independent Top20 candidate quality as the main gate: same candidate date, current strategy Top20 vs product baseline Top20, each candidate independently bought at D+1 open and exited by current sell logic. Cash, combination cap, existing real trades, and previous same-symbol transaction state are deliberately ignored.
- Portfolio backtest remains the real transaction truth, but it is a separate layer: BUY signal still must pass D+1 open, cash, limit-up/limit-down, rank and combination cap to become a real trade. It must not be used to explain whether a candidate itself is good.
- Persisted signal events must follow the same execution-pool Top20 as the real buy plan. Before the 2026-06-30 fix, `backtest_signal_events` recorded theoretical BUY rows for every `is_buy_candidate()` score, even if `candidate_execution_selected=false`; this could make stock timelines look as if a non-Top20 candidate was bought. Current code restricts theoretical BUY events and theoretical holdings to `execution_candidate_pool()`.
- Portfolio backtest reproducibility rule: default runs must not read historical candidate caches. Cache reuse is an explicit diagnostic mode only and is marked by `assumptions.signal_cache_reuse`.
- Full-range product promotion rule: do not select a new full product baseline unless portfolio return/win rate improve and candidate quality does not materially degrade. Quick-window candidate-ranking upgrades may be merged only after same-code control, independent candidate-quality verification, and real portfolio verification; they still require broader full-range validation before being called stable alpha.
- Default execution-pool ranking no longer uses成交量/准备度 opportunity adjustment or generic low-suction lifecycle bonus. Volume, active-money, and low-suction lifecycle features remain in read-only audits and base evidence, but `candidate_lanes.dragon_pullback_opportunity_score()` is now only `total_score + default_clean_watch_entry_opportunity_bonus`; `execution_volume_preparation_adjustment` is recorded as `0.0`.
- The former broad `stealth_low_suction_opportunity_bonus` production entry point has been removed, not merely set to zero. Narrow clean-watch profiles such as `clean_low_liquidity_first_lift`, `clean_low_liquidity_accumulation`, and `clean_active_support_divergence` remain explicit default execution bonuses because they map to verified 003004-style or support-accepted profiles rather than generic "low-suction days are many" logic.
- Default execution-pool selection now removes `stale_active_weak_decay_pullback`, `old_low_suction_strong_leg_normal_volume`, `large_bull_no_limit_ma20_stretch`, `old_ma10_support_no_limit_normal_volume_decay`, `old_ma10_support_ma5_stretch_decay`, `strong_leg_long_pullback_ma10_far_decay`, `core_active_strong_leg_shrink_ma10_upper_decay`, `wide_ma10_high_turnover_normal_volume_decay`, `wide_ma_no_low_suction_high_close_volume_decay`, `overheated_ma5_reclaim_ma10_far_decay`, `crowded_large_bull_no_limit_high_close_decay`, and `core_active_short_pullback_strong_leg_lift_decay` after the normal Top20 is selected, without backfilling lower-ranked candidates. This is a candidate-quality gate under the fixed D-day candidate contract, not a position/capital/capacity rule. `core_active_ma10_flat_mid_high_turnover_decay` is explicitly excluded from this list after the `0.1.41` regression.
- Default sells now include `guarded_highclose_giveback_stop`: for high-close or signal-day bad-bucket entries, after at least four visible holding bars, if MFE has reached `>=12%`, current return is `<=4%`, and drawdown from the visible high is `>=5.5%`, exit unless a current buy signal, active late-pullback right-tail protection, or strong MA10-continuation protection applies.
- Default `0.1.24` candidate ranking includes a no-switch candidate-quality score adjustment before final TopN sorting. It rewards mature low-suction first lift (`+1.4`) and recent active right-tail sources (`+0.8`), and demotes MA5 overextension, volume stall, low-suction buildup without fresh lift, crowded repeated large-bull-without-limit, weak-warning days without MA5 turn, and unreclaimed MA20. It also includes buy-position structure rules: light reward for recent active money at tradable MA5 distance with controlled close, light reward for controlled shrink-volume launch, and stronger demotion for no-limit high-close launches, active-but-stale low-suction without first lift, late high-position launches, active high-close MA5 extension, mature low-suction high-close confirmation without limit-up source, and active late high-position confirmation. Evidence records `candidate_quality_adjustment`, `candidate_quality_score`, `candidate_quality_base_score`, `candidate_quality_profile`, and `candidate_quality_notes`.
- Default `profit_protection_stop` remains active, but the medium-profit giveback branch is narrowed so it does not tighten exits for fragile historical/compatibility holdings that already have a profit buffer and no explicit setup marker.
- Backtest diagnostics now flag probable unadjusted-price discontinuities on both real trade paths and independent candidate paths. Main-board gaps like `-22%..-29%` are treated as data-quality contamination even when the raw `change_pct` is also extreme. Support-stop matrix exposes both raw buckets and `*_without_price_discontinuity` clean buckets.
- Quick `max_symbols` 股票池截断现在按最新流动性排序，而不是按 `vt_symbol` 代码排序。组合回测、每日候选生成和单股 trace 的股票池排名口径必须保持一致：`turnover DESC, market_cap DESC, vt_symbol`。
