## Current Strategy Mechanics

当前策略不是单纯的“突破 5 日线买入”。大致流程是：

```text
D 日收盘日线数据
  -> 全市场计算龙回头/低吸/低位承接因子
  -> BUY 候选按分数排序
  -> 组合只看执行候选前 20
  -> D+1 开盘尝试买入
       -> 未满仓: 买入
       -> 已满仓: 只有触发换仓规则才让位
  -> 持仓后按支撑止损/趋势回撤/浮盈保护/时间效率等卖出
```

`低吸蓄势` 的核心不是“每天都买”，也不是“只要突破 MA5 就买”。代码里的低吸结构至少需要：

- 最近反复低吸/承接，通常 `low_suction_days >= 3`；
- 股价靠近 MA5/MA10 或 MA20，且 MA20 没有明显破坏；
- MA5/MA10/MA20/MA30 收敛或正在改善；
- 量能不能放得过急；
- 风险、流动性、支撑修复不过硬失败。

`低吸启动确认` 更接近“蓄势后第一次可控上拉”：

- 普通确认：涨幅约 `0.8%..6.2%`，收盘在日内区间中上部，量比不超过约 `1.55`，仍靠近 MA5/MA10/MA20；
- 强启动：涨幅约 `6.2%..10.5%`，收盘位置更高，量能仍受控，均线更收敛且支撑天数足够。

所以用户说的“启动应该会逐步突破 5 日线”方向是对的，但在当前策略里 MA5 只是其中一个确认条件：允许靠近 MA5、MA10 或 MA20 的启动，不是硬性只看 MA5 突破。

## Proposed Default-Off Experiments

### 0. No-Position Top20 Factor Drilldown

目标：严格按用户要求彻底去掉 10 仓位限制，只研究“每天候选 Top20 本身为什么收益/胜率略强，但平均回撤和最差回撤略弱于基线”。

实验口径：

- 每个共同候选日分别看当前策略 Top20 和产品基线 Top20；
- 每只票独立 D+1 开盘入场，按当前卖点退出；
- 不看现金、不看最大持仓、不看满仓、不看已有持仓、不看换仓；
- 输出每个候选日当前 vs 基线的 Top20 股票、排名、分数、setup、行情阶段、最终收益、最大回撤；
- 最终仍按全体候选路径整体汇总，不只按单日胜负判断。

验收重点：

- 找出当前 Top20 回撤弱于基线的具体因子桶，例如未确认启动、低吸高位收盘、量能偏弱、退潮风险、龙回头偏早；
- 先证明候选层改进有效；真实组合执行实验只能作为后续诊断，不作为候选质量主验收。

### 1. High-Priority Winner Admission

目标：解决“当前看得到高质量候选，但满仓时不给让位”的问题。

实验规则只允许默认关闭：

- 当组合满仓时，若新候选满足 `rank <= 5` 或 `score >= 96`，且属于 `dragon_pullback` / `low_position_reclaim` 的高质量桶，进入让位评估；
- 不替换已明显走强的趋势赢家，例如浮盈较高、趋势未破、买后承接良好的持仓；
- 优先替换可见弱持仓，例如浮亏、持仓多日无效率、支撑/承接转弱、不是当前同股强信号；
- 需要记录被替换持仓、候选分数差、持仓浮盈浮亏、后续卖出原因，便于归因；
- 不允许使用未来收益决定换仓。

验收重点：

- `trend_trailing_stop` 趋势赢家笔数应从 `23` 向基线 `33` 修复；
- 收益、胜率必须同时超过当前 no-cache `#275`，最终还要通过产品基线 `#203/#194` 晋升门槛；
- 最大回撤不能继续恶化。

### 2. Risk-Off Low-Suction Launch Gate

目标：减少假强势/退潮防守环境下的低吸确认失败。

实验规则只允许默认关闭：

- 仅在 `market_warning_level >= 3`、`false_bull`、`panic_outflow`、`risk_off` 等高风险环境启用；
- `stealth_low_suction` 和低位承接类候选必须满足更窄的启动质量，例如 `balanced_first_lift` 或明确的强承接；
- 对启动未确认、量能偏弱但收盘过高、MA5/MA10 偏离过大、买后容易无承接的样本降级为 WATCH；
- 不在普通震荡/回暖阶段一刀切，因为候选层退潮和震荡仍有后验机会。

验收重点：

- `support_stop` 净亏应下降；
- 不能明显减少趋势赢家；
- 候选 Top20 cohort 不能显著劣化。

### 3. Support-Stop Replacement Cooldown

目标：避免“止损释放仓位后立刻买到下一只弱票”。

实验规则只允许默认关闭：

- 只针对 `support_stop` 且路径标记为假启动、低吸确认后无承接、强风险/假强势的卖出；
- 卖出后 `1..3` 个交易日内，新买入需要更高门槛，例如 `rank <= 5`、`score >= 96`、启动确认和市场风险不过高；
- 如果没有强候选，允许暂时持现金，不强行补满 10 仓。

验收重点：

- 替换票平均收益必须改善；
- 总交易次数可以下降，但收益/胜率/回撤必须改善；
- 不能像旧的宽泛替换质量实验一样错过趋势赢家。

### 4. Candidate Trace Wording Fix

这不是交易策略变更，但应修正用户解释：

- 当前 trace 会把“理论单股标记层已持有”放在前面，容易让人误解为真实组合被理论持仓压制；
- 报告和 UI 应优先展示真实组合状态：是否满仓、是否有真实持仓、是否触发换仓、是否下单；
- 理论标记账本只作为单股图形解释，不应掩盖真实组合执行原因。

当前候选质量主验收：

- 同候选日 Top20 当前策略 vs 产品基线；
- 每只候选票独立 D+1 开盘买入，按当前卖点退出；
- 不看现金、最大持仓、满仓、已有持仓或换仓；
- 主比较指标是全体共同候选日候选路径的平均收益、胜率、平均回撤和最差回撤；四项都不弱于基线，才说明候选质量改动具备进入下一步真实组合诊断的资格；
- 报告必须解释收益来自候选质量改善、减少亏损、恢复赢家，还是仅仅来自更高风险暴露。

## Recommendation

下一步不要先改 MA5/MA10 买点，也不要先扩大持仓数。优先顺序：

1. 先做无仓位 Top20 因子钻取，把每个候选日当前 Top20 与基线 Top20 的具体股票和后续收益拆开。
2. 只有候选层弱点清楚后，才评估是否需要改因子、排序或启动确认。
3. “高优先级赢家让位”、趋势赢家保护、止损后冷静期都归入真实组合诊断实验，不再混进候选质量主验收。
4. 再做风险环境下低吸启动门槛，专门处理假强势/退潮防守中的高分假启动。
5. 每次真正的策略改动先过统一 Top20 候选质量测试，再决定是否进入真实组合回测诊断。

本次仅调整测试口径，当前真实策略本来就没有变化；`#203/#194` 仍是产品默认，`#275` 只作为 no-cache 分析样本。
