# AlphaAgent 打板次交易时段观察设计

## 目标

让 `/limit-up` 在收盘后任何时刻都能展示下一交易时段的接力观察计划，并在次日竞价和盘中把候选从“提前观察”逐步更新为“接近触发、买点触发或条件失效”。页面不能因为尚无当日盘中快照而只显示“市场门关闭”。

第一版仍是人工研究工作台，不接自动下单。买点状态和执行许可分开表达：规则可以判定“买点已触发”，但 Tick/L2、逐日点时证据和冻结后前向验证未完成时，执行许可必须保持 `research_only`。

## 用户时序

### 收盘后

- 15:00-15:05：保留最后一笔盘中快照，并显示“次交易时段计划生成中”。
- 15:05：使用最终涨停池、炸板路径、最后盘中快照和当日可见板块信息生成 `preliminary` 初步计划。
- 19:00：日线、个股/板块资金和情绪数据完成后重新评估，生成 `final` 正式计划。
- 21:30：只在正式计划缺失或源交易日落后时补建，不用当日结果反向改写已经冻结的规则。
- 用户在收盘后、夜间、周末或节假日访问时，始终读取最近源交易日生成的下一交易时段计划。

计划使用 `source_trade_date` 和 `target_session=next_trading_session` 标识，不按自然日猜测下一个交易日期。下一次实时行情确认交易日后，再解析实际 `target_trade_date`。

### 次交易日竞价和盘中

- 09:15-09:19：合并计划候选和竞价指示数据，状态为 `pending_auction` 或 `approaching_trigger`，不可执行。
- 09:20-09:24：竞价强度、板位、板块、情绪和个股硬门全部通过时，状态升级为 `trigger_ready`；任一硬门失败则为 `invalidated`。
- 09:25-09:29：使用最终竞价结果冻结竞价判断；未满足条件的竞价计划过期，不能在盘中追高补买。
- 09:30-14:57：首板、扫板、回封和尾盘路径继续使用现有分钟扫描；候选可在 `observing / approaching_trigger / trigger_ready / invalidated` 间转换。
- 快照超过 90 秒、来源日期不等于当前交易日或关键字段缺失时，只允许观察，不得进入 `trigger_ready`。

## 方案选择

采用“持久化盘后计划 + 后台竞价状态机”。

不采用仅由前端展示上一日候选的方案，因为它没有统一的状态、审计和失效规则；不采用打开页面时直接访问行情源的方案，因为它会增加等待、限流和多人访问时的重复请求。

## 后端设计

### 计划生成

新增独立的次交易时段计划服务，职责是：

1. 从最后盘中快照、最终涨停/炸板事件和最新可靠日线加载源交易日候选。
2. 只保留沪深主板非 ST、板块龙一/龙二和市场龙 Top5。
3. 首板计划只用于次日一进二观察；二板计划用于二进三观察；高板必须继续满足现有分歧、换手、资金和成交可信度约束。
4. 每条计划保存生成时可见的板块、资金、情绪、量能、换手、封板路径、历史证据和战法验证结果。
5. `preliminary` 和 `final` 按时点追加保存，读侧优先返回同一源交易日的 `final`；下一交易日形成实际竞价证据后，盘后任务不得再改写当时状态。

第一版复用 `limit_up_signal_snapshots`，新增以下 `mode`：

- `next_session_preliminary`
- `next_session_final`
- 现有 `live_snapshot`
- 现有 `stale_snapshot`

盘后计划不是实时快照，不进入严格前向成交统计。实际交易时段保存的 `live_snapshot` 才能进入前向观察账本。

### 候选合并

竞价扫描必须显式携带正式计划中的股票代码，并获取这些股票的当时行情，不能只依赖涨幅榜前 200 名。计划外的新强股可以进入盘中动态 Top5，但不能把计划内股票因为没有出现在涨幅榜截断结果中误判为无数据。

计划候选与竞价行情按 `vt_symbol` 合并：

- 计划层提供前一交易日板位、封板质量、板块地位、历史证据和固定规则。
- 实时层只提供当前可见的竞价涨幅、成交额/量比、板块状态、情绪状态和数据时间。
- 最终动作只由当时可见字段决定；开盘后结果、最终封板和 D+1 收益只用于结果归因。

### 状态与权限

每条候选返回两个互不混淆的字段：

- `signal_state`: `observing | pending_auction | approaching_trigger | trigger_ready | invalidated | expired`
- `execution_permission`: `research_only | simulation_eligible | executable`

`signal_state=trigger_ready` 只表示量化买点条件已经满足。当前系统的数据门禁未通过时，`execution_permission` 必须是 `research_only`，页面显示“买点已触发（研究）”，不能显示成已获实盘许可。

### 结构化解释

每条计划和实时信号统一返回：

- `strategy_name`：首板、一进二、二进三、高板及形态标签。
- `selection_reasons`：最多四条最重要的入选原因。
- `trigger_checks`：按规则列出 `passed / pending / failed`、当前值、要求和证据时间。
- `buy_instruction`：买入阶段、价格条件和最晚有效时间。
- `sell_instruction`：D+1 动态竞价/尾盘退出规则。
- `cancel_checks`：开板、封单缩水、跌出 Top5、板块转弱、炸板率过高等取消条件。
- `plan_phase`、`source_trade_date`、`updated_at` 和数据质量。

解释必须来自实际规则字段，不允许由前端拼接与算法不一致的营销文案。

### 调度与补偿

- 新增 15:05 初步计划任务。
- `eod_1900` 在依赖数据完成后生成正式计划。
- `eod_finalize_2130` 只在正式计划缺失或落后时补建。
- API 启动时检查最新完整交易日是否缺少计划；缺少时后台单飞补建。
- 竞价扫描窗口提前到 09:15，仍保持每分钟单飞和 45 秒防重复。
- `GET /api/limit-up/live` 继续只读数据库/缓存，不访问外部行情、不写快照。

## 前端设计

实时区域保持单一列表，不增加嵌套卡片：

`股票与龙位 | 当前状态 | 战法与入选原因 | 触发检查 | 买入/卖出/取消规则 | 关键资金指标`

当没有当日 `live_snapshot` 时：

- 有正式计划：显示“次交易时段正式观察”，不显示“当前没有已保存的盘中快照”。
- 只有初步计划：显示“初步观察，等待盘后数据确认”。
- 两种计划都没有：显示“计划生成中/数据不可用”以及最近源交易日，不把它表述为市场门关闭。

状态用文字和克制的颜色区分：观察为中性、接近触发为警示色、买点触发为上涨色、失效为下跌色。所有状态同时显示数据时间；移动端按相同信息顺序换行，不隐藏买入、卖出或取消规则。

## 错误处理

- 15:05 数据源失败：保留最后盘中候选并标记 `degraded`，不能生成 `final`。
- 19:00 依赖数据不完整：继续展示 `preliminary`，明确缺失门，不把它升级为正式计划。
- 竞价行情过期或缺少计划股票：对应检查保持 `pending`，不得默认为通过。
- 调度重复触发：同一源交易日、计划阶段和策略版本幂等更新。
- 周末/节假日：计划继续可读，但不请求行情、不写实时快照。

## 验收标准

- 收盘后任意时刻打开页面，都能看到最近交易日产生的次交易时段观察计划或明确的生成状态。
- 周五计划在周末持续可见，并在下一个真实交易日激活，不把周六当成目标交易日。
- 09:15 后计划候选开始更新竞价检查；只有数据新鲜且全部硬门通过时才进入 `trigger_ready`。
- 计划股票不因涨幅榜 Top200 截断而消失。
- 每只股票都展示入选原因、逐项触发状态、买入点、D+1 卖出规则和取消条件。
- `trigger_ready` 与 `research_only` 可以同时存在，页面不会把研究触发冒充实盘许可。
- GET 实时接口保持只读；盘后计划和交易时段快照均可按时间审计。
- 后端单元/接口测试、调度测试、前端测试、生产构建及桌面/手机浏览器验收全部通过。
