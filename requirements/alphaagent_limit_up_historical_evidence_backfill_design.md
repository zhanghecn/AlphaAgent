# AlphaAgent 打板历史证据回补设计

## 目标

把当前只能前向积累的涨停事件路径和集合竞价快照改造成可历史回补、可审计、可在产品中操作的数据链路。导入结果用于替换日线代理和扩大严格研究样本，不直接解除 Tick/L2 门禁，也不承诺收益。

## 数据边界

- 股票范围固定为沪深主板非 ST，不包含创业板、科创板、北交所和退市/特殊状态股票。
- 涨停事件由系统查询同花顺公开历史和 Tushare `limit_list_d`，至少保留首次封板、最后封板、开板次数、封单额和连板数。
- 集合竞价由系统查询 Tushare `stk_auction`，保留价格、成交量额、昨收、换手和量比。Tushare 不提供未匹配量，因此只能形成部分竞价证据，相应严格门禁不得解除。
- 产品不接受用户 CSV、本地文件或复制数据库作为历史证据来源。
- 历史数据的 `captured_at` 记录实际导入时间；行情时点写入 `source_updated_at/source_quote_time`，不得伪装成系统当时已实时采集。

## 架构

独立历史证据导入服务负责供应商查询、主板过滤、完整度审计和逐交易日原子替换。服务复用现有 `stock_events`、`stock_auction_snapshots` 与数据质量门禁，不修改 vn.py 核心。

数据管理页“打板证据”工作区显示供应商配置、官方可用范围、数据库覆盖和最近结果；支持同花顺一键补齐，以及选择 Tushare 事件/竞价、日期范围、预检查或写入。所有失败均返回结构化日期级原因，已存在的可靠日期不会被空响应覆盖。

## 验收

- 无 Tushare token 时明确返回 `unavailable` 且不泄露配置值；同花顺能力按自身可用性独立报告。
- CSV、模板、本地文件和数据库复制入口不存在，对应旧 HTTP 路径返回 `404`。
- 供应商错误、过期日期、非交易日、空响应和覆盖不足都不写库。
- 同一日期重复导入幂等；单日写入要么完整成功，要么保留旧数据。
- 数据质量接口自动反映新增事件/竞价覆盖；缺未匹配量时 `simulation_eligible` 继续为 `false`。
- 后端、前端、生产构建、真实接口和桌面/移动端均验证通过。
