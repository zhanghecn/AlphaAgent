# AlphaAgent 动态大盘画像与回踩低吸策略设计

日期：2026-06-18
对象：`mainline_dragon_pullback / 0.1.21`、回踩低吸/龙回头统一策略、动态大盘/主线画像审计
结论性质：工程设计与回测审计，不构成投资建议；所有收益、胜率和分桶结论只代表当前本地数据样本。

## 摘要

AlphaAgent 当前普通产品入口只保留一个公开策略：`mainline_dragon_pullback / 0.1.21`。它不是把“低吸洗盘”和“龙回头”拆成两个 UI 策略，而是在同一公开策略下作为两个内部 setup 处理：

- `stealth_low_suction`：低吸洗盘，核心是均线附近反复承接、缩量、MA20 不破、回撤受控、均线收敛改善，随后出现第一个温和拉升确认。
- `dragon_pullback` / `TAIL_BUY_READY`：经典龙回头，核心是前面已有强势主升或涨停资金痕迹，回踩 MA5/MA10/MA20 后重新转强。

本轮落地的是“动态大盘/主线画像审计层”，不是新买卖规则。它把每个候选信号日放进大盘状态中复核：强势、震荡、弱势、快速杀跌、窄幅主线牛、假强势等。UI 上不增加新的操作按钮，只在 `/quant` 回测首屏展示年度分段、大盘环境、Top10 候选审计和动态市场分桶。

当前本地数据存在限制：没有指数日线，`sector_period_scores` 只覆盖 2026-06-12 到 2026-06-17。因此系统会降级为 `benchmark_return_20d_proxy`，即用 20 个交易日市场等权收益代理动态市场状态。这个代理能回答“强势/震荡/弱势/杀跌里候选表现如何”，但还不能严格证明“科技主线回踩”或“非科技轮动新主线”。文档和 UI 都必须明确显示该来源。

## 1. 用户问题拆解

用户提出的核心问题可以拆成四类：

1. 科技主线下跌时，正好是龙回头回踩。如果系统把大盘下跌当成风险，会不会错过后续主线回踩启动？
2. 市场突然进入震荡期，不再是科技主线，反而某些非科技票进入低吸洗盘并启动，这种能不能抓到？
3. 突然进入熊市，最坏情况下只有少数票保持低吸启动状态，这种能不能抓到？是否应该提高阈值或降低仓位？
4. 如何全量测试有效性、通用性、胜率和收益，避免当前科技窄牛样本过拟合？

本设计的回答是：先把市场状态作为“审计维度”落地，证明候选在不同大盘环境中的真实表现，再决定是否把市场状态变成动态买入门槛、排序加权或仓位控制。不能先把“科技”写死进规则，也不能只看几只肉眼样本就改默认交易逻辑。

## 2. 最终公开策略口径

### 2.1 一个公开策略

普通用户只看到一个策略：

| 字段 | 当前值 |
| --- | --- |
| 策略 ID | `mainline_dragon_pullback` |
| 版本 | `0.1.21` |
| 展示名称 | 主线龙回头回踩低吸 |
| 候选展示 | 评分前 100，分页每页 20 |
| 组合执行 | BUY 候选前 20 |
| 最大持仓 | 10 |
| 执行模型 | D 日收盘信号，D+1 日线开盘执行 |

旧策略 `mainline_leader_pullback`、`breakout_confirmation`、`limit_up_after_pullback`、`trend_acceleration` 只保留为内部兼容和历史对照，不再作为普通用户多个策略入口。

### 2.2 买点定义

买点只分三层：

| 层级 | 含义 |
| --- | --- |
| 原始形态信号 | 低吸/龙回头结构存在，可能只是观察 |
| 可执行 BUY | 分数、风险、流动性和失败规则通过，可进入组合候选 |
| 真实成交 | 组合排名、持仓上限、换仓、涨跌停、执行日 K 线都通过 |

低吸不是每天都画 BUY。低吸过程会逐步累计证据：MA5/MA10/MA20 附近承接、缩量、均线收敛、MA20 不破、回撤受控、小幅抬升。只有“低吸很久后，出现第一个干净上升/弱转强确认”才应成为关键买点。

### 2.3 卖点定义

当前卖点仍是组合状态机动态计算，不是固定靠买点高度位置卖出。后续应继续围绕以下方向优化：

- 入场后最高浮盈回撤。
- 当前支撑结构是否破坏。
- 当前日是否仍有有效买入/持有结构。
- 高位突然大幅回撤是否疑似出货。
- 不能把简单早期止损直接上线，因为 `0.1.19/#173` 和 `0.1.20/#174` 已验证会显著降低收益。

## 3. 动态大盘画像算法

### 3.1 完整算法

完整画像由四层组成：

1. 宽基指数层：上证、沪深300、中证500、中证1000、深成指、创业板、科创50 的趋势、动量、回撤和波动。
2. 市场广度层：全市场站上 MA20/MA60 的比例、上涨家数比例。
3. 主线板块层：`sector_period_scores` 的 20 日热度、广度、动量、资金和连续性。
4. 候选对齐层：候选股票是否属于当日主线板块，或者是否只是弱市里的独立强票。

目标分类：

| Regime | 中文 | 触发含义 |
| --- | --- | --- |
| `strong_broad` | 普涨强势 | 宽基、广度和动量同步好 |
| `narrow_theme_bull` | 窄幅主线牛 | 主线强但广度不强，例如科技窄牛 |
| `choppy_rotation` | 震荡轮动 | 大盘无单边趋势，主线可能切换 |
| `weak_defensive` | 弱势防守 | 宽基弱，风险预算应收缩 |
| `crash` | 快速杀跌 | 指数破位且波动/回撤高 |
| `false_bull` | 假强势 | 指数尚可但广度明显差 |

主线状态：

| Theme State | 含义 |
| --- | --- |
| `active` | 主线仍活跃 |
| `active_pullback` | 主线仍在，但正在分歧/回踩 |
| `emerging` | 新主线可能出现 |
| `risk_off` | 系统性风险优先 |
| `none` | 暂无可用主线 |

### 3.2 当前降级算法

因为当前本地没有指数日线，且历史板块评分不足，系统按 20 交易日市场等权收益代理：

| 20 日市场代理收益 | 动态画像 |
| ---: | --- |
| `>= +5%` | `strong_broad` 普涨强势 |
| `-3%` 到 `+5%` | `choppy_rotation` 震荡轮动 |
| `<= -3%` 且 `> -8%` | `weak_defensive` 弱势防守 |
| `<= -8%` | `crash` 快速杀跌 |

这个降级路径能用于过拟合审计，但不能用于精确行业主线判断。

### 3.3 如何处理用户提出的三种场景

| 场景 | 完整数据下的处理 | 当前数据下的处理 |
| --- | --- | --- |
| 科技跌时是龙回头 | `narrow_theme_bull + active_pullback`，不因大盘下跌直接误杀主线回踩 | 只能看 20 日市场代理，不能识别科技主线 |
| 震荡期非科技低吸启动 | `choppy_rotation + emerging/theme_related`，候选靠自身低吸蓄势和首次拉升排序 | 能看震荡桶胜率，但不能识别具体非科技主线 |
| 熊市少数票启动 | `weak_defensive/crash + isolated_candidate`，审计其胜率和超额收益，后续可转为高阈值/低仓位 | 已能按弱势/杀跌代理桶审计独立强票 |

## 4. 实现方式

### 4.1 后端文件

| 文件 | 作用 |
| --- | --- |
| `alphaagent/server/services/quant/market_context.py` | 计算市场画像、代理降级、候选主线对齐、分桶汇总 |
| `alphaagent/server/services/backtest/queries.py` | Top10 候选审计、固定 20 日观察、批量市场基准、动态画像接入 |
| `tests/alphaagent/test_quant_backtest_portfolio.py` | 单元测试动态分桶、代理降级、Top10 汇总和批量基准 |

### 4.2 API 输出

`GET /api/backtests/{id}/top-candidate-audit?top_n=10` 增加：

- `summary.dynamic_market_buckets`
- `summary.theme_alignment_buckets`
- `summary.candidate_observation.dynamic_market_buckets`
- `summary.candidate_observation.theme_alignment_buckets`
- `items[].dynamic_market_source`
- `items[].dynamic_market_regime`
- `items[].dynamic_market_label`
- `items[].stock_theme_alignment`

### 4.3 前端展示

| 文件 | 作用 |
| --- | --- |
| `frontend/src/api/quant.ts` | 增加 Top10 审计类型 |
| `frontend/src/features/quant/BacktestAnalysis.tsx` | 展示年度/大盘/Top10/动态画像/主线对齐审计 |
| `frontend/src/features/quant/BacktestPanel.tsx` | 回测首屏加载 Top10 审计 |
| `frontend/src/features/quant/BacktestTables.tsx` | 年度表空数据时不渲染 |

UI 只增加审计信息，不增加新操作。

### 4.4 未来函数控制

- 信号日只使用当日及以前的 K 线、板块、财报和资金数据。
- D 日收盘生成信号，D+1 开盘执行。
- 固定 20 日观察收益只作为审计标签，不参与买卖。
- 真实闭仓 Top10 只用组合真实买入并闭合的交易计算收益。
- 缺指数/板块数据时必须标记代理或 unknown，不能伪造主线。

## 7. 游资方法论如何量化

公开游资/短线打法可以转成以下可测因子：

| 经验说法 | 可量化因子 | 当前状态 |
| --- | --- | --- |
| 主线没死，只是分歧 | 主线热度、主题广度、指数回踩、候选属于主线 | 需要补历史板块评分 |
| 龙回头 | 强势第一波、回踩均线、缩量、支撑不破、再转强 | 已在策略内 |
| 低吸洗盘 | 多日均线承接、缩量、MA 收敛、回撤受控、小幅抬升 | 已在策略内 |
| 弱转强 | 低吸后第一根干净拉升/重新站回短均 | 已在策略内 |
| 熊市独立强票 | 弱市/杀跌桶里仍有相对强度和结构承接 | 已开始审计 |
| 高位派发 | 高位久横、放量滞涨、长上影、破支撑 | 已作为风险证据，未全部硬拒 |
| 大盘差要降仓 | 市场状态驱动动态阈值/仓位 | 待验证，不默认启用 |

不能直接量化或不能直接硬编码的部分：

- 某个固定席位就是某个游资本人。
- “科技一定是主线”这种固定行业判断。
- 单只股票肉眼样本直接变成硬规则。
- 只看收益不看排除强势市场后的胜率。

## 8. 下一步验收标准

动态市场算法要从审计层进入交易层，必须满足：

1. 补齐指数日线和历史板块评分。
2. 重新运行 `#190` 同区间审计，主线对齐不再大面积 unknown。
3. 用市场状态做动态阈值/仓位实验，必须生成新版本号和新回测编号。
4. 新版本必须同时比较：
   - 总收益。
   - 最大回撤。
   - 年度收益。
   - 强势/震荡/弱势/杀跌分桶胜率。
   - 排除强势行情后的 Top10 胜率和平均收益。
   - 目标股票的买点/卖点是否改善。
5. 如果收益或回撤弱于 `#190 / 0.1.21`，不能保留为默认策略。

## 9. 当前结论

当前最稳妥的落地方案是：

- 策略仍保留 `mainline_dragon_pullback / 0.1.21`。
- 低吸和龙回头仍是同一公开策略内的两个 setup。
- 动态大盘/主线画像先做回测审计和 UI 解释。
- 当前实证显示：排除强势市场后 Top10 候选仍有正收益和正超额，这是有价值的反过拟合证据。
- 当前还不能宣称牛熊都稳定有效，也不能宣称已经识别出科技主线回踩，因为本地指数和历史板块数据不足。
