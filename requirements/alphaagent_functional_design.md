# AlphaAgent 功能模块与执行流程设计

## 1. 目标

AlphaAgent 要做的不是一个让用户自己配置大量参数的量化工具，而是一个面向 A 股的智能选股与模拟交易系统。

用户最终关心的是：

- 今天/本周应该重点看哪些股票。
- 为什么选这些股票。
- 属于哪个板块、产业链、市场主线。
- 有哪些政策、新闻、资金、财务、技术指标支持。
- 当前市场是牛市、熊市、震荡市还是结构性行情。
- 风险在哪里，什么情况下不能买。
- 如果模拟建仓，买多少、怎么止损、怎么止盈。
- 如果回测，这套逻辑过去是否有效，在哪些行情里有效或失效。

系统要尽量减少用户配置。复杂参数由系统内置默认值和策略模板管理，用户只需要选择：

- 投资周期：长期、波段、短线。
- 风险偏好：保守、均衡、进攻。
- 是否允许模拟建仓。
- 是否只看某些行业或排除某些行业。

## 2. 产品最终效果

### 2.1 首页：今日决策面板

首页不是参数配置页，而是结论页。

需要展示：

- 当前市场状态：牛市、熊市、震荡市、结构性行情。
- 今日主线板块：例如算力、PCB、电力、半导体、光模块。
- 最近 30 天板块资金流向排名。
- 今日候选股票 Top 5。
- 每只股票的推荐等级、适合周期、建议动作。
- 当前不建议交易的风险提示。

每只股票卡片展示：

- 股票名称、代码、行业、概念。
- 龙头排名：行业/板块 1-4 名。
- 推荐理由摘要。
- 量化评分：质量、资金、趋势、估值、风险。
- Agent 理由：政策、新闻、产业链、市场误解、情绪。
- 风控建议：可买仓位、止损位、止盈位、失效条件。
- 操作按钮：
  - 查看完整理由。
  - 加入观察。
  - 模拟建仓。
  - 用当前策略回测。
  - 加入黑名单。

### 2.2 股票详情页：为什么选它

用户点进股票后，要看到完整解释链。

需要展示：

- 公司基础信息。
- 所属行业、概念、产业链位置。
- 是否为龙头，龙头依据是什么。
- 财务摘要：收入、利润、现金流、毛利率、ROE、负债率。
- 估值：PE、PB、PS、股息率、历史分位。
- 技术面：趋势、均线、成交量、换手、突破/回调。
- 资金面：个股资金流、板块资金流、龙虎榜/游资线索。
- 政策新闻：近期相关新闻、公告、政策催化。
- Agent 判断：市场是否可能误解、逻辑是否成立、催化是否强。
- 风险点：估值过高、业绩不支持、板块退潮、资金流出、黑名单原因。
- 理论知识解释：为什么这些指标重要，用通俗语言说明。

### 2.3 模拟建仓页

用户不需要自己写交易参数。系统根据风险偏好给出默认方案。

展示：

- 模拟资金。
- 建议仓位。
- 首次买入比例。
- 分批买入计划。
- 止损线。
- 移动止盈线。
- 最大允许亏损。
- 板块集中度限制。
- 当前是否允许买入。

操作：

- 一键模拟建仓。
- 调整风险偏好。
- 查看模拟持仓。
- 查看触发的风控规则。

### 2.4 策略测试页

用户关心的是策略是否靠谱，不需要先理解复杂回测参数。

展示：

- 策略名称，例如“主线龙头回调策略”、“长期质量龙头策略”、“资金流强势策略”。
- 回测时间范围。
- 适用市场环境。
- 年化收益。
- 最大回撤。
- 胜率。
- 盈亏比。
- 换手率。
- 交易次数。
- 牛市/熊市/震荡市分段表现。
- 与指数对比。
- 最差交易案例。
- 失败原因总结。

操作：

- 对某只股票回测。
- 对候选池回测。
- 对一个板块回测。
- 保存为策略模板。

## 3. 总体架构

```text
数据接入层
  -> 数据清洗与标准化层
  -> 股票池与黑名单层
  -> 市场环境识别层
  -> 板块资金与主线识别层
  -> 量化筛选层
  -> Agent 研究层
  -> 推荐解释层
  -> 风控与模拟交易层
  -> 回测与复盘层
  -> 服务端 API / 前端页面
```

vn.py 在 AlphaAgent 中主要承担：

- Gateway：未来连接券商、订阅实时行情、下单/撤单。
- Datafeed：历史行情数据接入。
- Database：保存历史 K 线、Tick 等本地数据。
- DataManager：辅助查看/导入/导出历史数据。
- MainEngine：未来作为交易核心，统一管理 Gateway 和交易行为。
- Object Model：复用 `TickData`、`BarData`、`ContractData`、`HistoryRequest` 等标准对象。
- AlphaLab：可用于本地因子研究、模型训练、信号和回测数据管理。

AlphaAgent 需要在 vn.py 之上新增：

- A 股数据服务层。
- 股票池管理。
- 板块资金分析。
- 市场环境识别。
- 选股评分引擎。
- Agent 研究引擎。
- 推荐解释引擎。
- 模拟交易账户。
- 风控引擎。
- 策略回测编排。
- 服务端 API。
- 用户界面。

## 4. 功能模块设计

### 4.1 数据源管理模块

目标：

- 接入全 A 基础数据、历史行情、板块、资金流、财务、新闻、政策。
- 隐藏复杂配置，用户只看到“数据状态是否正常”。

输入：

- vn.py Datafeed：`vnpy_xt`、`vnpy_rqdata`、`vnpy_tushare` 等。
- 未来可能补充的外部数据源：新闻、公告、产业链、资金流。

输出：

- 标准股票表。
- 标准行情表。
- 标准财务表。
- 标准板块表。
- 标准资金流表。
- 标准新闻/政策表。

vn.py 对接：

- `vnpy.trader.datafeed.get_datafeed()`
- `vnpy.trader.object.HistoryRequest`
- `vnpy.trader.database.get_database()`
- `vnpy.alpha.lab.AlphaLab`

默认策略：

- 用户不直接填写数据源细节。
- 系统提供“数据源配置向导”。
- 能自动检测缺失插件并提示安装。
- 数据质量异常时给出明确状态：缺行情、缺财务、缺板块、缺新闻。

### 4.2 股票池与黑名单模块

目标：

- 从全 A 股票中删除明显不适合交易的股票。
- 减少后续计算和 Agent 阅读量。

过滤规则：

- ST、退市整理、长期停牌。
- 流动性不足。
- 成交额过低。
- 财务异常。
- 连续亏损严重。
- 重大风险公告。
- 异常暴涨后风险过高。
- 用户手动拉黑。

输出：

- `all_universe`: 全 A 股票池。
- `tradable_universe`: 可交易股票池。
- `quality_universe`: 值得研究的优质股票池。
- `blacklist`: 风险黑名单。

用户看到：

- 今天排除了多少股票。
- 排除原因分布。
- 某只股票为什么被拉黑。

### 4.3 市场环境识别模块

目标：

- 判断当前行情，避免牛市/熊市污染策略判断。

输入：

- 大盘指数。
- 宽基指数。
- 行业指数。
- 上涨/下跌家数。
- 创新高/新低数量。
- 成交额。
- 波动率。
- 北向/主力资金，若数据可得。

输出：

- 市场状态：牛市、熊市、震荡市、结构性行情。
- 市场风险等级：低、中、高。
- 当前适合的策略类型。

初始规则：

- 指数趋势向上、成交放大、上涨家数扩散：偏牛市。
- 指数趋势向下、成交萎缩、下跌家数扩散：偏熊市。
- 指数横盘、板块快速轮动：震荡市。
- 指数一般但少数板块持续强势：结构性行情。

用户看到：

- 当前市场判断。
- 判断依据。
- 对仓位的影响。
- 该行情下哪些策略禁用。

### 4.4 板块资金与主线识别模块

目标：

- 找到市场资金正在流向哪里。
- 识别主线板块，而不是只看单只股票。

输入：

- 最近 30 天板块资金流。
- 板块涨跌幅。
- 板块成交额。
- 板块内涨停/强势股数量。
- 新闻/政策热度。

输出：

- 板块强度排名。
- 资金持续性排名。
- 主线板块列表。
- 退潮板块列表。

用户看到：

- 最近 30 天资金流向哪些板块。
- 哪些板块是短期热点。
- 哪些板块有长期产业逻辑。
- 板块内部龙头 1-4 名。

### 4.5 龙头识别模块

目标：

- 在主线板块里找最值得关注的 1-4 只龙头。

龙头依据：

- 市值。
- 收入/利润规模。
- 行业地位。
- 市占率。
- 技术壁垒。
- 资金流。
- 股价强度。
- 成交额。
- 机构关注度。
- 政策受益程度。

输出：

- 每个板块的龙头候选。
- 龙头排名。
- 排名理由。

用户看到：

- 为什么它是龙头。
- 是基本面龙头、资金龙头、情绪龙头，还是技术突破龙头。
- 龙头地位是否稳定。

### 4.6 量化筛选与评分模块

目标：

- 用确定性指标筛出一批候选股。
- 量化负责“缩小范围”，不是直接决定最终买入。

评分维度：

- 质量分：收入、利润、现金流、ROE、负债率。
- 成长分：收入增速、利润增速、行业空间。
- 估值分：PE、PB、PS、历史分位。
- 资金分：个股资金流、板块资金流、成交额。
- 趋势分：均线、动量、突破、回撤。
- 风险分：波动率、最大回撤、公告风险、财务风险。
- 龙头分：板块排名、行业地位、资金地位。

输出：

- 候选股池。
- 每只股票的评分明细。
- 排除原因。

用户看到：

- 量化筛选 Top N。
- 每只股票强在哪里、弱在哪里。
- 哪些股票分高但被风控拦截。

### 4.7 Agent 研究与解释模块

目标：

- 对量化候选池做高层研究判断。
- 给出“为什么近期可能涨”的解释。

Agent 处理内容：

- 政策新闻。
- 公司公告。
- 研报摘要。
- 产业链上下游。
- 市场误解。
- 题材持续性。
- 情绪热度。
- 失败案例对照。

Agent 输出：

- 推荐理由。
- 反对理由。
- 需要核验的假设。
- 催化事件。
- 失效条件。
- 置信度。

重要约束：

- Agent 不能直接编造事实。
- 对“主力洗盘”“市场误解”“政策受益”这类判断必须列出证据。
- 没有证据时标注为“待验证假设”。

用户看到：

- 一段人话解释。
- 引用到的新闻/公告/数据来源。
- Agent 为什么认为它值得关注。
- Agent 为什么可能错。

### 4.8 推荐决策模块

目标：

- 把量化评分、市场环境、板块主线、Agent 研究、风控结果合并成最终推荐。

输出：

- 今日 Top 5。
- 观察名单。
- 不建议买入名单。
- 风险黑名单。

每个推荐包含：

- 推荐等级：强关注、关注、观察、暂不买。
- 推荐周期：长期、波段、短线。
- 推荐原因。
- 主要风险。
- 建议动作。
- 买入失效条件。

用户看到的是结论，而不是配置项。

### 4.9 风控模块

目标：

- 先保护本金，再考虑收益。
- 避免过度恐惧导致卖飞。

风控规则：

- 单票最大仓位。
- 单板块最大仓位。
- 总仓位上限。
- 市场状态影响仓位。
- 单笔最大亏损。
- 最大回撤限制。
- 止损线。
- 移动止盈。
- 黑名单拦截。
- 高风险公告拦截。

输出：

- 是否允许买入。
- 最大可买仓位。
- 止损位。
- 止盈位。
- 持仓调整建议。

用户看到：

- 为什么能买/不能买。
- 买多少更合理。
- 亏到哪里必须退出。
- 涨到哪里开始保护利润。

### 4.10 模拟交易模块

目标：

- 在真实交易前验证选股和风控效果。
- 用户可以对推荐股票一键模拟建仓。

功能：

- 模拟账户。
- 模拟现金。
- 模拟持仓。
- 模拟买入/卖出。
- 交易日志。
- 持仓盈亏。
- 风控触发记录。

vn.py 对接：

- 可先独立实现模拟账户。
- 后续可接入 `vnpy_paperaccount`，基于实时行情撮合。
- 最终接入真实 Gateway 前，模拟交易必须先稳定。

用户看到：

- 当前模拟持仓。
- 每只股票买入理由。
- 当前盈亏。
- 风控是否触发。
- 是否还符合原推荐逻辑。

### 4.11 策略回测模块

目标：

- 验证选股逻辑和交易规则过去是否有效。
- 防止未来函数、幸存者偏差、过拟合。

回测类型：

- 单股回测。
- 候选池回测。
- 板块龙头回测。
- 市场环境分段回测。
- 风控规则回测。

vn.py 对接：

- `vnpy_ctabacktester` 可用于 CTA 类策略回测。
- `vnpy.alpha` 可用于多因子研究和策略研究。
- 后续多股票组合可考虑 `vnpy_portfoliostrategy`。

用户看到：

- 过去是否赚钱。
- 最大亏损有多大。
- 哪些市场环境下有效。
- 哪些情况下失败。
- 是否值得模拟建仓。

### 4.12 复盘与教训记忆模块

目标：

- 记录预测失败原因。
- 让系统逐步减少重复错误。

记录内容：

- 当时推荐理由。
- 实际走势。
- 市场环境。
- 板块变化。
- 新闻是否兑现。
- 资金是否撤退。
- 风控是否执行。
- 错误原因。
- 下次如何避免。

用户看到：

- 本周/本月预测成功率。
- 最大失败案例。
- 系统学到的教训。
- 哪些规则需要调整。

## 5. 每日执行流程

```text
1. 数据更新
   -> 更新行情、财务、板块、资金流、新闻、公告

2. 数据质量检查
   -> 检查缺失、异常、停牌、复权、重复数据

3. 全 A 股票池过滤
   -> ST/退市/流动性/财务风险/黑名单

4. 市场环境识别
   -> 判断牛市、熊市、震荡市、结构性行情

5. 板块主线识别
   -> 统计最近 30 天板块资金和强度

6. 龙头识别
   -> 每个主线板块排名 1-4

7. 量化评分
   -> 质量、成长、估值、资金、趋势、风险

8. 生成候选池
   -> 例如从全 A 缩到 50 只

9. Agent 研究
   -> 从 50 只中研究出 5-10 只

10. 风控检查
    -> 去掉不能买或仓位过高的标的

11. 输出今日推荐
    -> Top 5 + 理由 + 风险 + 操作建议

12. 用户选择
    -> 查看详情 / 模拟建仓 / 回测 / 加观察

13. 盘后复盘
    -> 记录预测结果和失败教训
```

## 6. 用户最少配置设计

用户不应该配置复杂指标权重。默认提供三套模式：

### 保守模式

- 更看重财务质量和回撤控制。
- 降低短线题材权重。
- 仓位更低。
- 熊市大幅降低交易频率。

### 均衡模式

- 同时看质量、资金、趋势、板块主线。
- 适合大多数情况。
- 默认模式。

### 进攻模式

- 更看重资金、趋势、题材、龙头。
- 容忍更高波动。
- 必须有更严格止损。

用户可以选择：

- 模式。
- 总资金。
- 最大可接受回撤。
- 是否允许短线。
- 是否只看自选行业。

其他参数系统内置。

## 7. MVP 阶段设计

### MVP 1：看得见股票和理由

目标：

- 接入全 A 基础信息和日线行情。
- 建立风险过滤。
- 建立基础量化评分。
- 输出候选股票和评分理由。

不做：

- 自动交易。
- 复杂 Agent。
- 真实下单。

### MVP 2：板块资金和市场环境

目标：

- 加入大盘状态识别。
- 加入板块资金流。
- 输出主线板块和龙头排名。

### MVP 3：Agent 研究解释

目标：

- Agent 阅读新闻、公告、政策。
- 对候选池给出 Top 5。
- 每只股票给出理由、风险、失效条件。

### MVP 4：模拟建仓

目标：

- 一键模拟买入。
- 持仓盈亏。
- 止损/止盈规则。

## 8. 需要结合 vn.py 的具体点

- `MainEngine`: 后续统一管理 Gateway/App。

- `HistoryRequest`: 统一历史数据请求。
- `BarData`/`TickData`: 行情数据对象。
- `ContractData`: 合约信息对象。
- `vnpy_sqlite`: 本地数据库。
- `vnpy_datamanager`: 历史数据管理 GUI。
- `vnpy_ctabacktester`: CTA 回测。
- `vnpy.alpha`: 多因子研究。

### 需要安装/评估的 vn.py 插件

- `vnpy_xt`: A 股历史/实时/财务等数据候选。
- `vnpy_rqdata`: A 股历史和实时行情候选。
- `vnpy_tushare`: A 股历史、财务、基础数据候选。
- `vnpy_xtp`、`vnpy_tora`、`vnpy_ost`、`vnpy_emt`: A 股交易 Gateway 候选。
- `vnpy_scripttrader`: 多标的脚本策略和扫描。
- `vnpy_portfoliostrategy`: 多股票组合策略。
- `vnpy_datarecorder`: 实时行情录制。
- `vnpy_paperaccount`: 模拟交易候选。

### AlphaAgent 自己要新增的代码层

建议未来新增独立目录，不直接混入 `vnpy/` 核心：

```text
alphaagent/
  api/              服务端 API
  data/             A 股数据源适配和标准化
  universe/         股票池、黑名单、行业/板块映射
  market_state/     牛熊/震荡/结构性行情识别
  sector/           板块资金和主线识别
  scoring/          量化评分
  research_agent/   Agent 研究、新闻公告解读
  recommendation/   推荐合成和解释
  risk/             风控
  simulation/       模拟交易
  backtest/         回测编排
  review/           复盘和教训记忆
  web/              前端或管理后台
```

注意：

- `vnpy/` 作为底层框架保留。
- `alphaagent/` 是你的上层业务系统。
- 这样不会破坏 vn.py 插件兼容性。

## 11. 当前未解决问题

- 当前 Python 3.13 环境下 A 股插件兼容性需要验证。
- vn.py 的回测模块更偏 CTA，A 股多股票组合回测可能需要补充自己的编排层。
- Agent 的新闻/政策来源需要确定，必须能给出来源，不能凭空判断。
- “主力洗盘”只能作为假设，必须转成可观测信号和回测规则。
