# AlphaAgent Requirement Map

本文件记录用户关于 AlphaAgent 的原始需求和整理后的结构。内容来自对话，不代表已经实现。

## 2026-06-07 原始目标

用户想基于 vn.py 做自己的 A 股量化系统，不只是看数据，而是逐步形成：

- A 股数据服务端。
- 自动量化筛选。
- Agent 智能选股。
- 板块/资金/政策/新闻/情绪联动分析。
- 风控优先的交易系统。
- 回测、复盘、失败教训记忆。
- 最终支持自动购买/交易执行。

## 核心问题

用户现在真正想要的是：

1. 把混乱的投资想法整理成系统设计。
2. 判断哪些想法能量化，哪些需要 Agent/人工判断。
3. 建立一个能从全 A 股缩小到少数候选股的流程。
4. 能解释为什么选这些股票，而不是黑盒推荐。
5. 能控制风险，避免赚不到钱或赚了又亏回去。
6. 能记录预测失败教训，持续修正策略。

## 初步系统分层

### 数据层

需要覆盖：

- 全 A 股票基础信息。
- 行情数据：日线、分钟线、Tick。
- 大盘指数：上证、深证、创业板、科创、沪深300、中证500/1000等。
- 板块/行业/概念数据。
- 最近 30 天板块资金流向。
- 个股资金流向。
- 龙虎榜/游资行为。
- 财务数据。
- 产业链数据。
- 政策新闻。
- 市场情绪。
- 风险黑名单数据。

### 量化筛选层

目标：

- 先从全 A 过滤出一批优质、风险较低、值得研究的股票。
- 减少 Agent 需要阅读和判断的数据量。
- 对风险股拉黑，降低噪声和误判。

可量化方向：

- 财务质量。
- 市值/估值。
- 成长性。
- 现金流。
- 行业龙头排名。
- 股价趋势。
- 成交量/换手率。
- 资金流入。
- 波动率。
- 回撤。
- 是否 ST/退市风险/财务异常。
- 是否处于主线板块。

### Agent 判断层

目标：

- 在量化候选池中，结合政策、新闻、产业逻辑、市场误解、情绪和资金面，选出近期可能上涨的少数股票。

适合 Agent 判断的方向：

- 政策催化是否真实重要。
- 新闻情绪是否持续。
- 市场是否误解公司业务，例如“法拉电子被误认为 MLCC，实际 SST 龙头”这类需要核验的观点。
- 产业链位置。
- 龙头是否真正受益。
- 主题是否有持续性。
- 主力洗盘/故意压盘这类无法直接证实的行为，需要谨慎转化为可观察信号。

### 市场状态层

必须判断当前环境：

- 牛市。
- 熊市。
- 震荡市。
- 局部结构性行情。
- 行业牛市/全市场熊市这类混合状态。

原因：

- 防止把牛市普涨误认为策略有效。
- 防止把熊市普跌误认为选股失败。
- 回测时需要按市场环境分组验证。

### 板块与主线层

用户关心：

- 电力。
- 算力。
- PCB。
- 半导体。
- 光模块。
- 国家政策指标。
- 稀缺资源。
- 板块资金流。
- 龙头排名 1-4。
- 产业链。

核心思想：

- 先找市场主线。
- 再找主线中的龙头。
- 再找龙头中估值/资金/技术/情绪更合适的标的。

### 交易周期层

用户区分：

- 长期持有：优质股票，长期大概率上涨。
- 短期做 T：围绕持仓或强势股做波段。
- 游资/龙回头：强势题材回调后的二次机会。

这些应该拆成不同策略，不能混用一个买卖规则。

### 风控层

用户明确强调：

- 风控最重要。
- 不亏钱才能赚钱。
- 留住钱才是王道。
- 但不能过度恐惧导致卖飞。
- 必须跟随市场情绪，同时识别可能的洗盘。

需要设计：

- 仓位控制。
- 止损。
- 止盈/移动止盈。
- 最大回撤限制。
- 单票风险限制。
- 板块集中度限制。
- 黑名单。
- 交易前风险检查。
- 交易后复盘。

### 回测层

必须避免：

- 未来函数。
- 幸存者偏差。
- 过拟合。
- 牛市污染。
- 数据质量问题。

回测要按市场环境拆分：

- 牛市表现。
- 熊市表现。
- 震荡市表现。
- 行业主线行情表现。
- 极端下跌表现。

### 自动交易层

未来目标：

- 自动购买。
- 自动撤单/止损/止盈。
- 自动风控。

需要准备：

- 券商交易 Gateway。
- 账户权限。
- 交易接口配置。
- 下单风控规则。
- 日志与审计。
- 人工确认开关。
- 模拟盘/小资金实盘验证。

## 量化 vs Agent 初步划分

### 更适合量化过滤

- 全 A 股票池过滤。
- ST/退市/财务异常过滤。
- 流动性过滤。
- 市值/估值筛选。
- 财务指标打分。
- 行业龙头排序。
- 资金流排名。
- 趋势/动量/回撤/波动率。
- 板块强弱。
- 牛熊/市场状态识别。
- 回测和风险统计。

### 更适合 Agent 筛选

- 政策和新闻解读。
- 产业链逻辑。
- 公司业务真实主营与市场误解核验。
- 题材持续性判断。
- 事件催化强弱。
- 研究报告/公告解读。
- 选出候选池中最有叙事和催化的 5 个标的。
- 失败教训总结。

### 需要特别谨慎的判断

- “主力故意洗盘”不能直接当事实。
- 应转化为可观测信号，例如：
  - 缩量回调。
  - 关键均线支撑。
  - 大单/资金没有明显流出。
  - 板块强而个股短暂弱。
  - 回调后快速收复。
  - 机构/游资席位行为。

## 第一版产品流程

1. 获取全 A 数据。
2. 过滤风险股票，形成黑名单。
3. 建立基础质量评分，得到长期候选池。
4. 建立市场环境识别，判断牛/熊/震荡/结构性行情。
5. 统计最近 30 天板块资金流向，找到主线板块。
6. 在主线板块中找龙头 1-4 名。
7. 对候选股做资金面、技术面、估值面过滤。
8. Agent 读取政策、新闻、产业链、公告、市场情绪，给出近期最可能上涨的 5 个候选。
9. 风控模块决定是否能买、买多少、何时止损/止盈。
10. 回测验证规则，按市场环境分组评估。
11. 实盘前先模拟盘/小资金，记录预测失败教训。

## 待验证问题

- 哪个数据源能低成本覆盖全 A 基础信息、历史行情、板块资金、财务、龙虎榜。
- vn.py 现有插件中哪些能直接支持这些数据。
- 是否需要自建数据服务补齐资金流/新闻/产业链。
- “法拉电子 = SST 龙头、市场误认为 MLCC”这一说法需要事实核验。
- 牛熊识别算法需要定义具体指标和阈值。
- 龙头排名 1-4 需要定义依据：市值、收入、利润、市占率、涨幅、资金流、板块地位。

## 2026-06-10 量化选股、回测与持仓补充

用户新增重点：

- 找到疑似洗盘后准备拉升的股票。
- 找到疑似主力偷偷试探的股票。
- 财报累积、经营现金流逐步变好作为排序加分项，不是强制项。
- 找到最近 1-2 个月大盘弱时仍然坚挺的股票。
- 找到趋势方向、季度利润改善、回踩 5 日线附近，适合尾盘低吸的机会。
- 对选出的股票模拟买入和卖出时机，统计胜率、盈利和回撤。
- 支持持仓分组、用户自选加入、量化结果自动加入持仓/候选、实时显示股票信息和成本价。

整理结论：

- “主力洗盘”“偷偷试探”不能作为事实字段，应转换为可观测代理信号，例如缩量回调、关键均线支撑、相对强度、放量试探压力位、板块未退潮等。
- “尾盘到 5 日线附近低吸”需要分钟级数据才能真实验证；日线阶段只能做收盘后近似回测，并明确标注不是尾盘级验证。
- 回测必须按历史每个交易日滚动重新选股，不能用今天选出的股票回看过去收益。
- 持仓自动化初期只能进入模拟持仓或量化候选，不能直接实盘下单。
