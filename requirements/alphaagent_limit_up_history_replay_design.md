# AlphaAgent 打板历史回放与因子研究设计

## 目标

在现有 `/limit-up` MVP 上增加可审计的历史交易日回放。用户切换日期后，应看到该日按当时可见代理数据生成的市场龙 Top5、最终封板结果、代理成交状态以及 D+1 开盘/收盘净收益。历史回放不得用当日最终封单金额、最终开板次数或收盘是否封住参与候选排序。

## 方案取舍

可选方案有三种：

1. 只给现有盘后快照增加日期参数。实现最少，但会把日终结果用于历史选股，存在明显未来函数。
2. 预先落库每日榜单。审计能力最好，但当前只有 21 个事件交易日，新增持久化表和迁移收益有限。
3. 按日期即时重建历史榜单，并与现有代理回测共用排序函数。第一版采用此方案；数据补齐后再升级为盘中快照落库。

## 接口

- `GET /api/limit-up/dates`：返回有涨停/炸板事件的可用交易日、最早日和最新日。
- `GET /api/limit-up/dashboard?date=YYYY-MM-DD`：返回指定交易日历史回放；未传日期时取最新事件日。
- `GET /api/limit-up/backtest?start=&end=&exit_mode=`：保留区间代理回测，并增加市场龙位、板位、首次触板时段、开板次数和换手区间分桶。

指定日期不存在时，dashboard 返回 `status=empty`，同时保留可用日期导航，不静默跳到其他日期。

## 历史排序边界

历史候选排序只使用：

- 前一可用交易日的板块资金流。
- 目标日前一交易日的连板身位代理和成交额。
- 当日候选首次触板时间；它表示触板后才产生候选，不表示开盘前预知。
- 当前概念成员快照，仅作为已知的数据缺口明确标注。

当日最终是否封住、最终开板次数、最终封单金额只用于结果评估和成交代理，不进入历史候选分数。09:31 前封死且没有开板的秒板仍判不可成交。

## 页面

页面顶部日期工具条包含前一交易日、日期选择器、后一交易日和刷新。切换后同步更新：

- 所选日情绪周期，不使用当前日情绪覆盖历史日。
- 当日封板/炸板、最高板、Top5。
- 每个 Top5 的最终状态、保守成交状态、D+1 开盘和收盘净收益。
- 所选日板块资金采用的历史资金日期。

回测区展示总体结果和因子分桶。分桶只在最小闭合样本数达到 5 时标记为可解释；更小样本仍显示，但标记样本不足。第一版不基于这 21 日小样本自动调权。

## 游资方法的量化边界

公开短线方法归纳为可验证因子族，而不是席位身份规则：

- 情绪准入与退潮空仓。
- 主线资金和板块扩散。
- 龙头、低位补涨与中位股排除。
- 分歧回封和弱转强。
- 封板质量与排队可成交性。
- 次日溢价和退出质量。

后续默认策略升级必须通过 walk-forward 样本外验证，同时提高净收益和胜率、降低最大回撤，且结果跨情绪阶段稳定。公开文章或席位归纳只作为假设来源，不作为已验证结论。

## 验收

- API 能准确导航 21 个已有事件交易日。
- 历史日 Top5 不因当日最终封板结果被过滤。
- 页面日期、情绪、榜单和 D+1 结果同步切换。
- 回测分桶的样本数加总与闭合交易一致。
- Python 定向测试、前端构建和桌面/手机浏览器验收通过。
