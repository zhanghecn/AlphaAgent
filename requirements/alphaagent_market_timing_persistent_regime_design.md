# AlphaAgent 金银手指持续行情状态设计

## 问题

当前系统同时存在两种不同语义：

- 金银手指事件：某个交易日产生候选，并在下一交易日确认或否决。
- 当日候选区域：最新因子是否仍满足某类金区或银区条件。

`overview.current_direction` 目前读取当日候选区域。只要最新交易日不再满足
候选条件，就返回 `NEUTRAL`。这会把金银手指误解为只在触发日附近有效的脉冲，
不符合面向用户的行情语义：一个手指出现后，市场持续处于该手指代表的行情，
直到相反手指完成确认。

## 目标语义

- 金手指和银手指仍是方向事件，不代表仓位、加减仓或交易指令。
- 最近一次已确认的手指决定当前行情状态。
- 已确认金手指从其 `confirm_date` 起形成金行情，直到已确认银手指反转。
- 已确认银手指从其 `confirm_date` 起形成银行情，直到已确认金手指反转。
- `PENDING` 候选不改变行情状态；`INVALIDATED` 候选不改变行情状态。
- 第一个已确认手指出现之前为 `NEUTRAL`。
- 状态只能从确认日起向后生效，未来事件不得回写更早日期。

## 方案选择

采用后端生成完整逐日行情状态，前端只消费统一结果。

不采用以下方案：

- 前端直接用 `latest_signal.direction` 覆盖摘要：只能修正单个页面，其他 API
  消费者仍会得到错误的 `current_direction` 语义，也无法审计逐日状态。
- 直接把 `zone_direction` 改成持续状态：会丢失当日是否命中候选区的诊断信息，
  并破坏现有测试和历史数据契约。

## 后端设计

### 持续状态序列

在市场择时领域层增加纯函数，根据交易日序列和事件序列生成逐日
`active_direction`：

1. 初始状态为 `NEUTRAL`。
2. 按交易日顺序处理。
3. 只读取 `status=CONFIRMED` 且 `confirm_date` 等于当日的事件。
4. 当日确认金则状态切换为 `GOLD`，确认银则切换为 `SILVER`。
5. 无新反转确认时沿用上一交易日状态。

该函数不读取收益标签、未来行情或事件之后的数据。截断输入到任意日期时，该日
及之前的状态必须与完整输入一致。

### 面板载荷

- `overview.current_direction` 改为最新交易日的 `active_direction`。
- `overview.latest_signal` 继续返回最近一次已确认事件，作为当前状态来源和起始日。
- `timing_series` 每行新增 `active_direction`。
- 原 `zone_direction` 保留，仍表示当日是否命中金银候选区域。
- 信号检测阈值、setup、候选日期、确认状态和回测统计不变。

## 前端设计

### 当前摘要

- 指环继续读取 `overview.current_direction`，但文案明确为“当前行情”。
- 金或银状态下展示本轮状态的确认起始日，并说明持续到相反手指确认。
- 只有样本期内从未出现已确认手指时才显示“无信号”。
- 不把 `PENDING` 候选显示成已经生效的行情反转。

### 最近交易日表

- 增加“行情状态”行，读取每日 `active_direction`，显示“金行情 / 银行情 / 中性”。
- 原“当日区域”行改名为“候选区域”，继续展示原始因子是否进入候选区。
- “手指事件”行继续展示候选、确认、否决信息，三种概念互不替代。

## 数据流

```text
因子序列 -> 候选事件 -> 次日确认状态
                         |
                         v
交易日 + 已确认事件 -> active_direction 序列
                         |
                         +-> overview.current_direction
                         +-> timing_series[].active_direction
                         +-> 当前摘要和最近交易日表
```

## 边界处理

- 空因子或空事件序列：当前状态和逐日状态均为 `NEUTRAL`。
- 同方向再次确认：更新本轮状态来源为最近一次已确认同方向事件，但方向不变。
- 相反方向待确认：保持原状态，确认后才在确认日切换。
- 相反方向被否决：保持原状态。
- 事件确认日晚于面板最后交易日：不得提前生效。
- API 盘中载荷若尚未满足收盘确认口径，不得把候选当作已确认反转。

## 验收标准

- `2026-06-11` 金手指在 `2026-06-12` 确认后，后续中性候选日仍显示金行情，
  直到出现已确认银手指。
- 金状态期间出现 `PENDING` 或 `INVALIDATED` 银候选，状态仍为金。
- 银状态期间出现已确认金手指，从金手指确认日起切换为金。
- `overview.current_direction` 与最后一条 `timing_series.active_direction` 一致。
- 修改未来事件或未来行情，不改变此前任何交易日的 `active_direction`。
- 历史金银事件数量、日期、setup、状态和准确率统计保持不变。
- 后端目标测试、前端组件测试、前端生产构建通过。

## 非目标

- 不调整金银手指识别算法或阈值。
- 不把危险状态、亏钱效应或普通弱势直接定义为银手指。
- 不引入仓位、重仓、买卖、策略开关或下单逻辑。
- 不改变金银事件的回测收益口径。
