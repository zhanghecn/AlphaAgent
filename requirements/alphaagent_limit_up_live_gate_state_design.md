# AlphaAgent 实时打板触发状态修复设计

## 1. 问题与目标

当前实时推荐会长期显示“硬门未过，今日不买”，候选接近或到达涨停后仍未出现可操作买点。已保存的 2026-07-14 盘中快照证明存在三类问题：

1. D-1 情绪偏弱时，盘中修复只由相邻两帧的封板、炸板增量确认。增量下一帧归零后，市场门立即重新关闭。
2. D-1 弱势同时进入全局市场门和接力板个股硬门。即使盘中修复，全局门与板位门仍可能互相矛盾。
3. 市场修复、距板距离、板块扩散和资金等可变化条件，与涨停基因、低位、基本面等结构性风险共用 `invalidated/rejected`，页面无法区分“继续等待”与“今日排除”。

本次目标是让合格候选在封板前稳定经历“观察 -> 接近买点 -> 买点触发”，同时保留真正的风险过滤，不以放宽全部门槛来制造推荐。

## 2. 决策

采用日内市场状态机、结构硬门与动态确认分层的方案。拒绝以下两种替代方案：

- 只改提示文案：不会修复市场门抖动，也不会产生真实触发。
- 删除市场门或统一放宽阈值：会把盘中已观察到的回落、炸板候选升级为买点。

## 3. 市场修复状态机

市场状态只在同一交易日内继承，跨交易日必须重置。

- `pending_repair`：D-1 为冰点、退潮或下降，盘中尚未出现修复证据。
- `repair_confirmed`：主板封板不少于 5 只、实时炸板率不高于 35%，并且某次快照出现封板增加且炸板减少。
- `repair_revoked`：确认后出现主板封板少于 5 只、实时炸板率高于 35%、快照过期或来源日期错误。

`repair_confirmed` 在后续健康快照中保持，不因相邻帧增量为零而消失。进入 `repair_revoked` 后，只有再次出现完整修复证据才能恢复。

市场门返回当前状态、首次确认时间、撤销原因和证据快照时间。非交易时段、过期快照和来源日期错误继续 fail-closed。

## 4. 门禁分层

### 4.1 结构硬门

以下条件失败时，候选状态为 `rejected`，当日不得升级为买点：

- 非沪深主板、ST 或特殊状态股票。
- 对应战法要求的涨停/触板基因不足。
- 首板不属于低位或充分回调后的首次涨停。
- 已披露严重基本面风险，或战法明确要求但点时财务证据缺失。
- 接力板前板路径、板位结构、龙头地位或风险栈未通过。
- 高板盘中接力缺少现行规则要求的 L2 证据。

### 4.2 动态确认项

以下条件未满足时不得触发买入，但状态保持 `observing` 或 `approaching_trigger`：

- 市场尚在等待修复。
- 首板尚未到 10:00，或价格尚未进入扫板距离。
- 板块热度、触板扩散、板块/个股资金和换手尚未达到当前执行阈值。
- 候选尚未进入或已暂时跌出当前可执行排序。

动态条件必须输出结构化检查项，包括实际值、要求值和证据时间。页面不得再把它们统一显示为“今日不买”。

### 4.3 D-1 弱势去重

D-1 情绪只负责决定市场状态机是否从 `pending_repair` 开始。盘中 `repair_confirmed` 后，二进三和高板不得继续仅因 `market_retreat/market_failed_rate_high` 重复否决；其余板位结构、行业、前板和风险条件保持不变。

## 5. 信号状态与触发

- `observing`：进入雷达，但距离或动态确认项尚远。
- `approaching_trigger`：结构硬门通过，已接近执行区，只剩一个或多个动态确认项。
- `trigger_ready`：市场状态、结构硬门、当前执行条件和封板前可见性全部通过，输出 `research_action=buy_now`。
- `missed`：未出现真实 `trigger_ready` 就已经封板，不允许事后补记买点。
- `rejected`：结构硬门失败。
- `invalidated`：曾接近或触发后，价格、市场或数据质量条件失效。

扫板距离、板块热度、扩散和资金判断必须由同一个执行检查函数产生。不得出现内部按热度 60/触板 3 只否决，页面却只提示“等待进入 1%”的隐藏条件。

战法样本外验证仍只控制自动 `action` 和执行许可，不得覆盖已经真实出现的 `research_action=buy_now` 或 `signal_state=trigger_ready`。产品继续明确为人工确认、研究用途。

## 6. 候选保留与两日轨迹

当前组合仍以最多 4 只、同板块最多 2 只为执行边界。候选一旦进入 `approaching_trigger` 或 `trigger_ready`，即写入当日轨迹；即使随后跌出动态 Top5，也保留最终状态和消失原因，不使用旧价格继续产生买点。

两日轨迹补充以下点时字段：

- 市场修复状态、确认时间、市场门原因。
- 板块热度、板块触板数、板块与个股主力净流入。
- 换手、距板距离、封单和封单变化。
- 结构硬门、动态确认项、组合入选状态和真实研究动作。

轨迹只用于审计，不反向修改正式推荐。

## 7. 界面

实时组合保持单一列表，不增加策略开关或解释卡片。每只候选只显示一个主状态：

- `买点触发（人工确认）`
- `接近买点，还差 N 项`
- `等待市场修复`
- `硬性排除`
- `已封板，错过不追`
- `条件失效`

主行显示最关键的一项缺口；展开现有轨迹后显示全部实际值、阈值和时间。状态排序为：买点触发、接近买点、等待观察、错过、硬性排除、失效。

## 8. 验证

### 8.1 单元测试

- 修复确认在健康的零增量快照中持续有效。
- 炸板率超过 35%、封板不足 5 只或数据过期会撤销确认。
- 撤销后必须再次出现完整修复证据才能恢复。
- D-1 冰点的二进三在修复确认后不再被重复市场原因否决，其他结构风险仍生效。
- 动态条件未满足时为 `approaching_trigger`，结构风险失败时为 `rejected`。
- 所有执行条件通过且尚未封板时才为 `trigger_ready`。
- 未触发即封板时只记录 `missed`。

### 8.2 2026-07-14 逐帧回放

对比原策略与修复策略：

- 市场门开放次数、持续时间和撤销原因。
- `observing/approaching_trigger/trigger_ready/rejected/missed` 数量。
- 触发时点是否早于封板。
- 触发后封板率、炸板率及未触板率。
- 已知回落、炸板候选不得因本次状态修复自动绕过结构和执行条件。

### 8.3 回归与产品检查

- 运行全部打板后端测试、相关调度测试、前端测试和生产构建。
- 在桌面和移动端验证实时列表、状态切换、两日轨迹、无重叠和无控制台错误。
- 历史回测结果不得因纯实时状态修复发生变化；如需调整执行阈值，必须作为独立研究版本重新做滚动样本外和锁定留出比较。

## 9. 非目标

- 不承诺每日必须出现买点。
- 不通过当天已知结果反向调参。
- 不把日线或公共行情代理描述为真实排队成交。
- 不启用自动下单，不改变 `research_only` 边界。
