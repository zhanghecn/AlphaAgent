# AlphaAgent 打板手动重算回测设计

## 状态

- 设计日期：2026-07-15。
- 用户已批准：正式环境可从 `/limit-up` 回测页手动重建历史账本并查看当前版本结果。
- 产品范围：复用现有全历史重建和状态接口，不改变选股、撮合、仓位或收益算法。

## 问题

当前回测页的“运行回测”图标仅重新请求 `GET /api/limit-up/history/backtest`。服务端会缓存
回测报告 6 小时，而且历史候选来自已持久化账本，因此部署新策略代码后，刷新页面不能保证
结果对应当前代码。

## 交互

1. 回测工具栏使用带文字的“重新计算”按钮，避免把普通查询刷新误认为完整回测。
2. 点击后调用现有 `POST /api/limit-up/history/rebuild`，由服务端后台线程重建完整历史账本、
   清理旧报告缓存并预热当前版本回测。长任务不得阻塞 HTTP 请求或页面。
3. 重建期间按钮禁用并显示“计算中”，页面轮询 `GET /api/limit-up/history/status`；用户仍可
   阅读上一次结果，但必须明确其正在更新。
4. 服务端返回“已有任务运行”时，页面接入该任务继续轮询，不重复启动第二次重建。
5. 完成后自动刷新可选日期、当前日期交割单、实时页组合回测摘要和当前区间回测，并显示
   完成提示。失败时保留旧结果并显示服务端错误，不伪装成新结果。
6. 页面重新打开时读取历史状态；若后台仍在重建，按钮直接恢复“计算中”状态。

## 接口与边界

- 保留 `GET /history/backtest` 为只读报告查询，不在 GET 请求中隐式触发重计算。
- 复用现有 `POST /history/rebuild` 与 `GET /history/status`，只补齐前端类型和调用函数。
- 手动重算始终执行完整历史重建，不能只清回测缓存；否则当前代码与旧历史候选仍可能不一致。
- 不新增参数面板。开始、结束日期只控制页面展示区间，不缩小持久化历史重建范围。
- 页面关闭不会取消服务端任务；重新打开后可继续查看状态。

## 验证

- 前端 API 测试覆盖启动请求和历史状态读取。
- 页面行为验证覆盖空闲、运行中、已有任务、成功刷新和失败保留旧报告。
- 后端现有重建测试继续证明单任务互斥、完成后清缓存并预热回测。
- 生产构建和 Docker 页面验证按钮可点击、任务期间不重复提交、完成后报告发生刷新。
